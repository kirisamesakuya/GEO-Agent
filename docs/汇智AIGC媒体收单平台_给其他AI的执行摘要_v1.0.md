# 汇智AIGC媒体收单平台给其他AI的执行摘要 v1.0

版本：v1.0  
日期：2026-06-25  
用途：可直接贴给其他 AI / Agent 作为启动提示

---

## 1. 任务背景

当前项目是“汇智AIGC媒体收单平台”，已有接单端、发布端、平台端基础页面与报价撮合逻辑，但整体体验仍偏粗糙，更像 Demo，而不像成熟交易平台。

本轮优化目标不是继续堆后端，而是：

1. 优先提升前端体验
2. 优先补强业务逻辑表达
3. 优先做成可演示、可评审、可继续接入真实后端的产品化前端

注意：

1. 本地后端和数据库不是本轮重点
2. 真实线上环境有独立数据库与后端体系
3. 当前开发应以 Mock-first、接口预留、ViewModel 先行为原则

---

## 2. 总体执行原则

请严格遵守以下优先级：

1. 用户体验
2. 前端业务逻辑完整性
3. 视觉与交互一致性
4. Mock 数据完整度
5. 接口契约清晰度
6. 本地后端联通

这意味着：

1. 不要因为本地接口不完整就把页面做粗糙
2. 不要直接围绕数据库字段写页面
3. 要先把页面结构、状态机、空态、错误态做完整

---

## 3. 设计方向

统一设计结论：

1. **任务工作台、任务大厅、报价页、订单页、财务页、账户页：参考巨量星图**
2. **入驻欢迎页、身份分流页、入驻流程页：参考小红书蒲公英**
3. **品牌色可偏红，但高频任务工作区不能被大面积红色主导**
4. **主工作区气质必须专业、克制、高效、可扫读**

色彩策略：

1. 品牌红：入驻、品牌识别、局部强调
2. 工作台蓝：高频操作、筛选选中、信息型主按钮
3. 风险红：异常、驳回、超时
4. 绿色：完成、通过、可结算

---

## 4. 页面开发规则

### 4.1 先判断页面属于哪一类

1. 如果页面核心任务是“处理任务 / 报价 / 订单 / 财务 / 账号管理”
   - 按巨量星图型页面做
2. 如果页面核心任务是“入驻 / 选择身份 / 欢迎引导”
   - 按蒲公英型页面做

### 4.2 页面必须有这些基础状态

每个页面都必须包含：

1. 加载态
2. 空态
3. 错误态
4. 正常数据态
5. 长文案态
6. 边缘状态

### 4.3 页面不能出现这些问题

1. 像原始表单拼出来的后台
2. 只有数据，没有“下一步动作”
3. 空状态时页面结构散掉
4. 同一状态在不同页面文案不一致
5. 工作台页面大面积营销化

## 5. 当前最重要的页面

如果你只负责一部分，请优先做这些页面：

### A. 接单端核心页

1. `ProviderHomeView`
2. `ProviderTaskView`
3. `ProviderSubmitQuoteView`
4. `ProviderQuotesView`
5. `ProviderOrderView`

目标：

1. 让接单方能发现任务
2. 能理解是否值得报价
3. 能提交结构化报价
4. 能管理报价和订单生命周期

### B. 接单端账户与财务页

1. `ProviderProfileView`
2. `ProviderAccountView`
3. `ProviderEarningView`
4. `ProviderOnboarding`

目标：

1. 让账户中心更可信
2. 让财务页更像成熟平台
3. 让入驻流程更顺滑

### C. 发布端核心页

1. `QuoteCompareView`
2. `CreateOrderView`
3. `DeliveryPlanView`
4. 发单管理相关列表页

目标：

1. 让品牌方能理解任务
2. 能看懂报价
3. 能选择方案，不只是看价格

### D. 平台端轻运营页

1. 接单方轻审核页
2. 履约评分页
3. 供给列表页

目标：

1. 让运营方看得懂供给质量
2. 让审核页具备后台感

## 6. 关键页面要求

### 接单端首页

参考：巨量星图概览页

必须有：

1. 待完成事项
2. 收益摘要
3. 公告通知
4. 推荐任务
5. 任务空状态

### 任务大厅

参考：巨量星图任务大厅

必须有：

1. 筛选器
2. 状态 Tab
3. 匹配度与匹配原因
4. 建议区间
5. 任务详情

### 报价提交页

必须有：

1. P0 到手价
2. 成交价 G 自动计算
3. 平台费 F 自动计算
4. 超区间提醒
5. 履约承诺
6. 交付证明选项

### 比价页

必须有：

1. 接单方
2. 认证状态
3. 可发媒体
4. 成交价 G
5. 最早上线时间
6. 交付承诺
7. 选用动作

禁止：

1. 向发布方展示 P0
2. 向发布方展示平台费 F

### 账户中心

参考：巨量星图账户管理页

必须有：

1. 基础信息卡
2. 认证状态卡
3. 媒体绑定卡
4. 报价规则卡
5. 案例与能力卡

### 财务页

参考：巨量星图财务页

必须有：

1. 摘要说明
2. KPI 小卡
3. 筛选器
4. 表格
5. 空状态
6. 分页

---

## 7. 数据实现要求

### 7.1 必须 Mock-first

每个页面先做：

1. ViewModel
2. Mock 数据
3. adapter
4. 页面完整状态

再接真实接口。

### 7.2 不要直接吃数据库字段

页面应消费 ViewModel，不直接消费 Prisma / API 原始对象。

建议至少抽这些类型：

1. `TaskMarketplaceCardViewModel`
2. `QuoteSubmissionViewModel`
3. `QuoteCompareRowViewModel`
4. `ProviderTrustProfileViewModel`
5. `ProviderFinanceOverviewViewModel`

### 7.3 接口只做契约

本轮不要求重做真实后端，只要求：

1. 路径清晰
2. 状态清晰
3. 输入输出稳定
4. 可被 Mock 替代

---

## 8. 工程与体验硬约束

1. 不要把业务判断散在 JSX 里
2. 不要让同一状态在不同页面有不同中文名
3. 不要新增与现有状态机冲突的状态
4. 不要跳过空态和错误态
5. 不要为了演示方便把页面做成一次性样子货
6. 不要让工作台页长得像营销页面
7. 不要让入驻页长得像冷后台表单
