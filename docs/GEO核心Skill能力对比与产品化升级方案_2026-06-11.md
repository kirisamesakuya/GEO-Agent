# GEO 核心 Skill 能力对比与产品化升级方案

> 对比对象：本项目 `geo-cn-skills`、`yaojingang/yao-geo-skills`、`aaron-he-zhu/seo-geo-claude-skills`  
> 结论日期：2026-06-11  
> 产品原则：Hermes 是执行环境，客户购买的是可信诊断、可执行内容和可验证增长。

# 1. 核心结论

本项目当前具备完整的 Skill 路由、统一 JSON 契约、国内平台适配和真机采样框架，技术骨架已经超过普通 Demo。但离可收费的生产级 GEO 产品仍有明显距离：过去主要验收“任务能否完成、字段能否落库”，而客户真正验收的是“报告能否用于汇报、建议能否落地、文章能否通过质量门禁、发布后能否用同口径数据证明变化”。

本次升级将产品完成标准从 `Hermes run completed` 调整为：

> 有证据的客户结论 + 可执行的 90 天方案 + 可发布的内容资产 + 发布前后实验与谨慎归因。

# 2. 三方能力对比

| 维度 | 本项目升级前 | yao-geo-skills | seo-geo-claude-skills | 本项目目标 |
|---|---|---|---|---|
| 国内 AI 平台真机采样 | 已有五平台框架 | 强，强调独立采样口径 | 偏海外引擎与通用连接器 | 保留优势并补重复采样、证据完整率 |
| 客户报告 | 主要是 JSON + 简单 HTML/Markdown | 强，四格式、管理层交付、公开样例 | 强，按受众生成绩效报告 | 一页摘要 + 完整证据 + 90 天路线 + 多格式 |
| 全景诊断 | 有模块清单和总分 | 强，12 域、事实交叉验证、站内外机会地图 | 分散在多类 Audit | 补齐诊断覆盖、证据覆盖和完成门禁 |
| 内容质量 | CORE-EEAT 快扫 | 强，产物与质量门禁 | 很强，80 项 CORE-EEAT 和阻断机制 | 核心项强制门禁，禁止虚构事实和来源 |
| GEO 内容生成 | 有定义、FAQ、来源要求 | 强，榜单/解释/对比等专项交付 | 强，Prompt 覆盖与候选引用块 | 输出可发布正文、目标 Prompt、引用块、来源台账 |
| 效果监测 | 有命中率、提及率和 T+7/14/30 概念 | 很强，稳定性、准确率、纠偏与归因 | 强，周期报告、指标来源标签 | 增加候选率、推荐率、有效引用率、稳定性和对照组 |
| 归因边界 | 尚不完整 | 明确四档归因置信度 | 明确观察与解释分离 | 只允许观察变化、可能相关、中/高置信归因四档 |
| Eval | 主要结构校验 | 路由、契约、内容、回归四层 | Skill Contract、Decision Gate、Auditor Gate | 建立黄金样本、对抗样本和真实复测集 |
| 业务完成标准 | 返回成功即大体完成 | 产物与质量门禁完成 | Done when 与 SHIP/FIX/BLOCK | 新增 deliveryStatus、qualityGate、nextBestAction |

# 3. 升级后的核心客户旅程

1. **建立基线**：围绕购买决策问题，在五个平台完成至少两轮真机采样。
2. **形成诊断**：区分事实、内容、结构、技术和外部信源问题，给出证据覆盖率。
3. **生成方案**：输出 30/60/90 天行动路线，明确 Owner、工作量、交付物和验收指标。
4. **生产内容**：每篇内容绑定目标 Prompt、品牌事实和来源，通过发布质量门禁。
5. **真实发布**：记录内容版本、平台、URL 和时间，建立实验处理对象。
6. **持续复测**：T+7、T+14、T+30 使用固定口径复测，并保留原始回答与截图。
7. **报告变化**：展示品牌出现率、候选率、推荐率、引用率、准确率和竞品差距。
8. **谨慎归因**：有对照和足够样本才提升归因置信度，否则只描述观察变化。

# 4. 正式报告必须回答的问题

- 当前品牌在什么购买问题、什么平台中被提及、成为候选或被推荐？
- AI 如何描述品牌，哪些事实正确，哪些错误或缺失？
- AI 引用了哪些来源，官网和第三方证据分别占多少？
- 主要竞品为什么更容易出现或被推荐？
- 未来 90 天应该先改页面、补证据、发什么内容、去哪发布？
- 每项动作由谁做、需要多少工作量、怎样算完成？
- 发布后指标是否变化，变化是否稳定，能否排除平台波动和外部事件？

# 5. 产品级验收指标

| 类别 | 最低标准 |
|---|---|
| 契约 | 必需字段和产物完整率 100% |
| 真实性 | 虚假引用 0；关键事实冲突 0 |
| 证据 | 正式报告关键结论证据覆盖率 >= 80% |
| 报告 | 管理层摘要、证据、机会、路线、验证计划章节齐全 |
| 内容 | 每个目标 Prompt 有独立回答块，关键 CORE-EEAT 项无未解决 Fail |
| 采样 | 失败不计未命中；环境、Prompt 版本、时间与原文可追溯 |
| 效果 | 基线与 T+7/14/30 同口径；处理/对照 Prompt 可区分 |
| 归因 | 无充分对照时不作确定性因果承诺 |

1. 建立至少 5 个真实行业黄金项目集，每个项目包含 T0 与发布后复测数据。
2. 为六个核心 Skill 建立路由、契约、内容、回归和对抗 Eval。
3. 把报告 `SHIP/FIX/BLOCK` 门禁接入正式 UI，`BLOCK` 产物禁止直接对客户发布。

5. 用真实发布项目验证 30 天闭环，产品验收从“接口成功率”升级为“客户交付通过率与可观测指标改善率”。
