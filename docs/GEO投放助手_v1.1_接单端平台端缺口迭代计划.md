## 1. 补充背景

主 PRD v1.1 已重点展开发布端，但接单端和平台端仍停留在概要层，缺少页面级功能、交互、数据对象、接口和验收标准。真实产品开发不能只完成发布端表单，也不能用 mock 接单方、mock 任务、mock 平台监控替代真实闭环。

本补充计划用于补齐：

1. 接单端从入驻、接任务、交付、返修到结算状态的真实链路。
2. 平台端从审核、派单、Agent 监控、订单监管到系统配置的真实运营能力。
3. Hermes Skill、有接口调用和本地电脑自动化的运营监控与审计。
4. 缺失数据对象、接口和迭代优先级。

|---|---|---|---|

## 3. 接单端页面功能详情

### 3.1 接单端工作台

#### 页面目标

让接单方登录后知道今天最应该处理的任务，减少错过接单、交付和返修的风险。

#### 页面结构

| 区域 | 内容 |
|---|---|
| 顶部摘要 | 入驻状态、可接任务数、待交付数、返修数、待结算金额 |
| 今日待办 | 待确认接单、即将截止、返修待处理、平台审核反馈 |
| 推荐任务 | 按能力标签和服务平台推荐 |
| 最近订单 | 最近 5 条订单状态 |
| 通知消息 | 平台通知、商家沟通、系统提醒 |

#### 关键交互

1. 未入驻或审核未通过时，工作台主 CTA 指向入驻申请。
2. 有超时风险订单时，顶部展示橙色提醒。
3. 推荐任务只展示接单方能力范围内的任务，超范围任务不进入首屏。
4. 点击待办可直接进入对应订单或审核反馈。

#### 实现方案

1. 后端提供 `ProviderDashboardSummary` 聚合接口。
2. 待办由订单状态、审核状态、返修状态和系统通知计算。
3. 推荐任务由任务类型、平台、预算、服务区域和能力标签匹配。

---

### 3.2 入驻申请

#### 页面目标

收集服务商真实能力资料，使平台可以审核并用于任务匹配。

#### 表单步骤

| 步骤 | 字段 |
|---|---|
| 基础信息 | 联系人、手机号、微信/邮箱、主体类型、所在地 |
| 服务能力 | 服务类型、擅长平台、行业标签、服务区域、可接预算 |
| 资源证明 | 账号截图、过往案例、链接、报价说明 |
| 结算资料 | 收款方式、结算主体、发票能力，可后置 |
| 提交确认 | 信息摘要、承诺条款、提交审核 |

#### 状态

| 状态 | 中文显示 | 可操作 |
|---|---|---|
| draft | 草稿 | 编辑、提交 |
| submitted | 待审核 | 查看、撤回 |
| approved | 已通过 | 更新资料 |
| rejected | 已驳回 | 查看原因、重新提交 |
| suspended | 已暂停 | 联系平台 |

#### 关键交互

1. 草稿自动保存。
2. 提交前必须至少选择一种服务类型。
3. 案例链接和附件至少提供一种。
4. 驳回后展示平台审核意见，并保留历史提交版本。
5. 审核通过后才允许申请接单。

#### 实现方案

1. `ProviderProfile` 保存基础资料。
2. `ProviderApplication` 保存每次提交版本。
3. `ProviderCapability` 保存服务类型、平台、行业和区域。
4. `ProviderAsset` 保存案例附件和链接。
5. 平台端审核写入 `ProviderReviewLog`。

---

### 3.3 资源管理

#### 页面目标

让接单方维护可用于匹配任务的账号、案例、报价和能力标签。

#### 功能点

| 功能 | 说明 |
|---|---|
| 平台账号 | 小红书、知乎、公众号、网站、其他渠道 |
| 案例库 | 图文、问答、探店、SEO/GEO、网页设计案例 |
| 报价设置 | 按任务类型设置报价区间 |
| 服务区域 | 全国、本地城市、线上服务 |
| 能力标签 | 医疗、教育、本地生活、美业、B2B 等 |

#### 关键交互

1. 平台账号可标记“可公开给商家看”或“仅平台审核可见”。
2. 报价区间会影响任务推荐，但不直接等于最终成交价。
3. 案例删除不影响历史订单证据。

---

### 3.4 任务大厅

#### 页面目标

展示可接任务，并帮助接单方快速判断是否适合申请。

#### 页面结构

| 区域 | 内容 |
|---|---|
| 筛选栏 | 类型、平台、预算、行业、城市、截止时间、验收方式 |
| 任务卡片 | 标题、品牌、预算、交付物、截止时间、匹配度、状态 |
| 右侧摘要 | 当前筛选、能力匹配说明、接单规则 |
| 空状态 | 引导完善能力或放宽筛选 |

#### 关键交互

1. 未登录可浏览部分任务，但申请接单必须登录。
2. 未审核通过用户点击申请时进入入驻页。
3. 匹配度低的任务可展示，但需要提示缺少能力标签。
4. 任务卡展示验收方式，避免接单后争议。
5. 已满员或已指派任务不再允许申请。

---

### 3.5 任务详情与申请接单

#### 页面目标

让接单方在申请前充分理解需求、交付物、验收标准和风险。

#### 页面内容

| 模块 | 内容 |
|---|---|
| 任务摘要 | 品牌、类型、预算、平台、截止时间 |
| 需求详情 | 商家目标、内容方向、关键词、禁用词 |
| 交付要求 | 链接、截图、文档、数据复盘、页面预览 |
| 验收标准 | 截图证明、链接回传、人工确认、数据复盘 |
| 风险提示 | 禁用词、平台规范、预算限制 |
| 申请接单 | 接单说明、预计交付时间、补充报价 |

#### 关键交互

1. 申请接单前必须勾选“已理解交付物和验收标准”。
2. 可填写接单说明，供商家或平台选择。
3. 若平台采用派单制，申请后进入“待平台确认”。
4. 若任务支持抢单，申请成功后生成订单分配记录。

#### 实现方案

1. `TaskOrderApplication` 记录申请。
2. `ProviderOrderAssignment` 记录最终接单。
3. 申请成功后写通知给商家和平台。

### 3.6 我的订单

#### 页面目标

管理接单方所有已申请和已接任务。

#### Tabs

| Tab | 状态 |
|---|---|
| 全部 | 所有订单 |
| 待确认 | 申请中、待平台确认 |
| 执行中 | 已接单、进行中 |
| 待验收 | 已提交交付物 |
| 返修中 | 商家要求返修 |
| 争议中 | 平台介入 |
| 已完成 | 验收通过 |

#### 列表字段

任务标题、品牌、平台、预算、截止时间、状态、最近动作、操作入口。

#### 关键交互

1. 即将截止订单展示倒计时提醒。
2. 待验收订单不可重复提交，除非商家要求补充。
3. 返修中订单必须先查看返修原因。
4. 争议中订单展示平台处理状态。

---

### 3.7 订单交付详情

#### 页面目标

让接单方提交符合验收标准的交付物，并保留证据。

#### 交付字段

| 字段 | 说明 |
|---|---|
| 交付说明 | 本次完成内容摘要 |
| 交付链接 | 发布链接、问答链接、网页预览链接 |
| 截图证明 | 至少一张，按任务规则决定 |
| 附件 | 文档、表格、图片、压缩包 |
| 数据复盘 | 曝光、互动、收录、排名等可选字段 |
| 自检 checklist | 接单方提交前确认 |

#### 关键交互

1. 必填交付物缺失时不可提交。
2. 提交后订单进入“待验收”。
3. 交付历史不可删除，只能追加补充。
4. 支持保存草稿。

---

### 3.8 返修、争议与结算状态

#### 返修

1. 商家要求返修时，接单方收到通知。
2. 返修详情展示原因、要求、截止时间。
3. 接单方可补充交付物并再次提交。

#### 争议

1. 接单方可在验收超时、需求变更、商家拒收时申请平台介入。
2. 争议必须填写说明并提交证据。
3. 平台处理结论进入订单记录。

#### 结算状态

首版不做自动分账，但需要展示状态：

| 状态 | 说明 |
|---|---|
| 待验收 | 未达到结算条件 |
| 待平台确认 | 验收通过但平台未确认 |
| 待线下结算 | 进入线下付款流程 |
| 已结算 | 平台记录已结算 |

## 4. 平台端页面功能详情

### 4.1 运营看板

#### 页面目标

让平台运营第一时间处理影响履约和真实产品运行的异常。

#### 模块

| 模块 | 内容 |
|---|---|
| 今日待办 | 入驻待审、任务待派、Agent 失败、发布失败、争议待处理 |
| 风险订单 | 即将超时、返修多次、交付缺失、验收超时 |
| Agent 概览 | 今日任务数、成功率、失败率、平均耗时 |
| 资金提醒 | 入账待确认、余额不足任务、冻结异常 |
| 快捷入口 | 审核、重试、改派、处理争议 |

#### 关键交互

1. 待办按 P0/P1/P2 分级。
2. 点击待办进入对应处理页，并带筛选条件。
3. Agent 失败和自动发布失败必须在首屏展示。

### 4.2 Agent 任务监控

#### 页面目标

监控所有文章生成、GEO 分析、投放计划、网页生成、自动发布和账号校验任务。

#### 列表字段

任务 ID、任务类型、来源端、品牌、用户、执行器、Skill、状态、进度、耗时、创建时间、最近日志、操作。

#### 筛选

任务类型、状态、执行器、Skill、品牌、用户、时间、是否失败、是否需要人工处理。

#### 详情页

| 模块 | 内容 |
|---|---|
| 输入摘要 | 用户提交参数、品牌、平台、目标 |
| 执行轨迹 | queued、running、工具调用、Skill 调用、回调事件 |
| 输出摘要 | 标题、报告摘要、发布链接、网页预览 |
| 错误信息 | 用户可见错误、技术错误、堆栈摘要 |
| 操作 | 重试、取消、标记人工处理、查看业务对象 |

#### 实现方案

1. 读取 `AgentTask`、`AgentTaskLog`。
2. Skill 调用记录进入 `AgentSkillRun`。
3. 平台重试必须创建新的执行尝试，不覆盖旧日志。

---

### 4.3 Hermes Skill 与本地自动化监控

#### 页面目标

监管所有通过 Hermes Skill 接口或本地电脑自动化执行的任务，尤其是自动发布。

#### 功能点

| 功能 | 说明 |
|---|---|
| Skill 调用记录 | skill 名称、版本、输入摘要、输出摘要、耗时、状态 |
| 本地执行环境 | Windows 主机、PowerShell、浏览器、客户端、运行账号 |
| 自动发布证据 | 发布前摘要、发布后链接、截图、平台提示 |
| 权限与脱敏 | 不展示 token、cookie、密码 |
| 人工接管 | 自动化失败后转人工处理 |

#### 关键交互

1. 自动发布任务失败后，运营可查看失败截图和失败原因。
2. 运营可标记“需商家重新授权”“需人工发布”“可重试”。
3. 本地电脑自动化任务必须显示执行环境，不允许黑盒成功。

### 4.4 订单与交付监管

#### 页面目标

平台统一监管任务订单生命周期。

#### 功能点

1. 订单列表和高级筛选。
2. 任务详情。
3. 接单申请列表。
4. 人工派单/改派。
5. 交付物审查。
6. 返修记录。
7. 争议处理。
8. 状态人工修正，必须写审计。

#### 关键交互

1. 改派前展示当前接单方、交付进度和风险。
2. 人工修改订单状态必须填写原因。
3. 争议处理必须输出平台结论。

---

### 4.5 网站订单管理

#### 页面目标

管理发布端创建的网页需求、AI 预览和技术交付订单。

#### 功能点

1. 网站需求列表。
2. AI 网页预览查看。
3. 材料和附件管理。
4. 指派网页设计师或内部技术人员。
5. 交付预览链接。
6. 验收和返修。

#### 状态

草稿、待处理、预览生成中、待确认、执行中、待验收、返修中、已完成、已取消。

---

### 4.6 用户与审核

#### 页面目标

管理商家账号、接单方入驻、角色权限和禁用启用。

#### 商家管理

1. 商家列表。
2. 品牌数量、任务数量、余额、算力。
3. 禁用/启用。
4. 查看关联订单和 Agent 任务。

#### 接单方审核

1. 入驻资料详情。
2. 案例和账号审核。
3. 能力标签确认。
4. 审核通过、驳回、补充材料。
5. 审核日志。

#### 权限

1. 平台角色：运营、审核、客服、管理员。
2. 菜单权限和操作权限。
3. 敏感操作二次确认。

---

### 4.7 资金、算力与流水监管

#### 页面目标

平台监管投放余额、冻结、入账申请、AI 算力消耗和异常。

#### 功能点

1. 入账申请审核。
2. 冻结记录查询。
3. 释放和人工调整。
4. AI 算力赠送、同步、消耗、失败记录。
5. 异常流水提醒。

#### 关键规则

1. 投放余额和 AI 算力必须分池展示。
2. 人工调整必须填写原因并写审计。
3. 不做在线支付，所有入账为人工确认。

---

### 4.8 系统配置

#### 页面目标

维护真实产品运行所需的可配置规则。

#### 配置项

| 配置 | 内容 |
|---|---|
| 平台配置 | 小红书、知乎、公众号、网站、其他渠道 |
| 任务类型 | 种草、探店、问答覆盖、测评、网页设计、SEO/GEO 顾问 |
| 验收方式 | 截图证明、链接回传、数据复盘、人工确认 |
| 预算规则 | 最低预算、冻结比例、释放规则 |
| Skill 路由 | 业务动作到 Hermes Skill / 内部接口 / 本地自动化的映射 |
| 模型配置 | 默认模型、备用模型、超时、重试 |
| 自动化环境 | Windows 主机、浏览器路径、可用状态、健康检查 |

#### 关键交互

1. 配置变更需要记录版本。
2. 影响发布和资金的配置需二次确认。
3. Skill 路由配置必须支持启用/禁用和优先级。

### 4.9 审计日志

#### 页面目标

为真实运营和问题追溯提供全链路记录。

#### 必须记录

1. 用户登录、禁用、角色变更。
2. 品牌资料修改。
3. 账号绑定、解绑、授权校验。
4. Agent 任务创建、重试、取消、失败。
5. Hermes Skill 调用和本地电脑自动化执行。
6. 自动发布确认、发布成功、发布失败。
7. 预算入账、冻结、释放、调整。
8. 订单派单、改派、交付、验收、返修、争议。

## 7. 迭代拆分

### 7.1 Iteration A：接单端真实闭环

目标：让接单方可以真实入驻、看任务、申请接单、提交交付物。

范围：

1. 接单端工作台。
2. 入驻申请。
3. 任务大厅。
4. 任务详情和申请接单。
5. 我的订单。
6. 交付提交。

验收：

1. 未审核用户不可接单。
2. 审核通过用户可申请任务。
3. 平台可确认接单方。
4. 接单方可提交真实交付物。

### 7.2 Iteration B：平台审核与订单监管

目标：让平台能审核入驻、派单、改派、监管交付。

范围：

1. 运营看板。
2. 接单方审核。
3. 订单与交付监管。
4. 人工派单/改派。
5. 返修和争议处理。

验收：

1. 平台可审核接单方入驻。
2. 平台可派单或改派。
3. 平台可查看交付物和返修记录。
4. 争议处理必须写结论。

### 7.3 Iteration C：Agent 与 Hermes 运营监控

目标：让平台能监管真实 Agent 执行、Hermes Skill 调用和本地自动化。

范围：

1. Agent 任务监控。
2. AgentTask 日志详情。
3. AgentSkillRun 列表和详情。
4. LocalAutomationRun 列表和详情。
5. 自动发布证据查看。
6. 失败重试、取消、标记人工处理。

验收：

1. 文章生成、GEO 分析、自动发布任务都能进入监控。
2. Skill 调用有输入摘要、输出摘要和状态。
3. 本地自动化有执行环境和截图证据。
4. 自动化失败不会被标记成功。

### 7.4 Iteration D：资金、配置和审计

目标：补齐真实运营所需的资金、配置和审计能力。

范围：

1. 入账申请审核。
2. 预算冻结/释放监管。
3. AI 算力流水监管。
4. 系统配置。
5. Skill 路由配置。
6. 审计日志。

验收：

1. 入账和人工调整必须写审计。
2. 投放余额和 AI 算力分池展示。
3. Skill 路由可配置优先级。
4. 敏感配置变更保留版本。

## 8. 验收标准

### 8.1 接单端 P0

1. 接单方可以提交入驻申请。
2. 平台审核通过前不可申请接单。
3. 接单方可以查看与自身能力匹配的任务。
4. 接单方可以申请任务。
5. 接单方可以查看我的订单。
6. 接单方可以提交交付物，交付物写入数据库并可被平台/商家查看。

### 8.2 平台端 P0

1. 平台可以审核接单方入驻。
2. 平台可以查看 Agent 任务失败和自动发布失败。
3. 平台可以查看任务订单和网站订单。
4. 平台可以人工派单或改派。
5. 平台可以处理争议。
6. 平台可以查看审计日志。

### 8.3 Hermes 与自动化 P0

1. Hermes Skill 调用记录可查。
2. 本地电脑自动化执行记录可查。
3. 自动发布必须有用户确认记录。
4. 自动发布必须有成功链接或失败证据。
5. 自动化失败时进入待人工处理或可重试。

## 9. 风险与评审问题

1. 接单端首版是抢单模式、申请模式，还是平台派单模式。
2. 接单方是否允许看到商家完整品牌资料，还是只展示任务必要信息。
3. 自动发布失败后由商家处理、接单方处理，还是平台运营处理。
4. 本地电脑自动化运行在哪些 Windows 主机上，如何做健康检查。
5. Skill 路由配置是否由平台运营维护，还是研发配置。
6. 线下结算状态是否需要对接财务系统。
7. 接单方案例和账号截图是否需要脱敏展示给商家。
