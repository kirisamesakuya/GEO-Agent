# GEO 投放助手：本机发布账号管理迭代计划

版本：v1.2 账号绑定专项  
日期：2026-06-04  
关联页面：发布端 `账户 / 账号绑定`、账户余额、发布计划、内容发布、Hermes 本地自动化  
核心结论：这里的“账号绑定”本质不是平台开户或 API 授权，而是让用户在自己的电脑浏览器中登录平台账号，使 Hermes 可以基于本机登录态自动发布文章。

---

## 1. 背景与产品口径

当前页面叫“账号绑定”，容易被理解成平台后台的广告账号资产管理、OAuth 授权或 API token 管理。但实际业务逻辑是：

1. 用户在自己的电脑上打开小红书、知乎、微信公众号等平台登录页。
2. 用户手动完成登录、扫码或验证。
3. Hermes 通过本机浏览器环境识别该平台已经登录。
4. 后续发布文章时，Hermes 使用这台电脑上的登录态完成发布动作。

因此，本模块的产品口径应从“投放账号资产池”收敛为：

**本机发布账号管理 = 平台登录态检查 + 发布账号标记 + 品牌使用范围 + Hermes 发布可用性。**

这比“投放账号管理”更轻，也更准确。

---

## 2. 命名建议

不建议继续叫“投放账号管理”，因为它暗示要管理广告账户、余额、授权关系、分配规则，范围过大。

推荐命名：

| 位置 | 推荐文案 | 原因 |
|---|---|---|
| 发布端侧边栏 | 发布账号 | 最直接表达这些账号用于发布内容 |
| 页面标题 | 发布账号管理 | 保留管理感，但不扩大到广告资产 |
| 页面副标题 | 管理本机已登录的平台账号，供 Hermes 自动发布使用 | 明确本机登录态 |
| 原账号绑定按钮 | 去登录 | 用户实际动作是登录平台 |
| 原确认绑定按钮 | 我已完成登录，检测账号 | 贴合 Hermes 检测流程 |
| 授权状态 | 登录状态 | 避免误解为 OAuth 授权 |

导航建议：

```text
账户
- 发布账号
- 账户余额
```

如果希望继续合并，可以叫：

```text
账户
- 发布账号与余额
```

但当前阶段建议先保留两个入口，避免余额和本机登录态混在一起。

## 3. 与已有功能的合并关系

这个模块不应单独发展成复杂资产系统，而应和现有功能按以下方式合并：

| 现有功能 | 调整方式 | 说明 |
|---|---|---|
| 账号绑定 | 改名为发布账号 | 保留核心流程：打开平台登录页、检测登录态、复检、解绑 |
| 账户余额 | 保持独立或作为账号详情信息 | 余额是资金信息，不等于登录态 |
| 发布计划账号选择 | 使用发布账号的可用状态 | 只展示本机已登录且可发布的账号 |
| 内容库发布账号选择 | 使用发布账号的可用状态 | 不再单独维护一套账号列表 |
| 服务商资源账号 | 只同步“可发布平台”和“可用账号数量” | 不复制完整账号管理 |

合并原则：

1. 一个平台账号只维护一条发布账号记录。
2. 登录、检测、复检、解绑都围绕这条记录进行。
3. 发布计划和内容发布只读取“可用发布账号”，不各自维护账号状态。
4. 余额可以作为发布账号详情的一部分展示，但不要把余额管理并入登录态流程。

## 4. 使用场景

### 4.1 品牌自己发布

品牌方在自己的电脑上登录平台账号，Hermes 使用该电脑自动发布。

流程：

1. 用户进入“发布账号”。
2. 点击某个平台的“去登录”。
3. 系统打开平台官方登录页。
4. 用户完成扫码、验证码或密码登录。
5. 回到系统点击“我已完成登录，检测账号”。
6. Hermes 检测本机浏览器是否已登录，并读取可展示的账号名称。
7. 检测成功后，该账号可用于当前品牌发布。

### 4.2 服务商代运营

服务商在自己的电脑上登录服务商可操作的平台账号，Hermes 在服务商电脑上完成代发布。

注意：

1. 服务商电脑登录的是服务商实际可操作的账号。
2. 账号可以标记服务哪些品牌，但不需要做复杂的资产归属模型。
3. 品牌自有账号如果要交给服务商代运营，本质也是服务商在自己的电脑上完成登录，或者品牌远程配合扫码。
4. 系统要记录“该账号由谁的本机环境提供发布能力”。

### 4.3 集团品牌多子品牌

集团或子品牌在同一台运营电脑上登录多个平台账号，不同账号可用于不同子品牌。

处理方式：

1. 每个发布账号可标记适用品牌或子品牌。
2. 发布计划选择账号时按品牌过滤。
3. 不需要首期建设集团级账号池，只需要支持“适用品牌”字段。

## 6. 页面设计

### 6.1 页面结构

建议页面只保留三个区域，不做复杂四页签。

| 区域 | 内容 |
|---|---|
| 顶部概览 | 已登录平台数、需重新登录数、最近检测时间、Hermes 状态 |
| 发布账号列表 | 平台、账号名、登录状态、提供方、适用品牌、最近发布、操作 |
| 右侧或抽屉详情 | 登录指引、检测记录、适用品牌、发布记录 |

### 6.2 列表字段

| 字段 | 说明 |
|---|---|
| 平台 | 小红书、知乎、公众号等 |
| 账号名称 | 检测成功后显示真实账号名，未检测前显示平台名 |
| 登录状态 | 已登录、未登录、已失效、检测失败 |
| 提供方 | 品牌方、服务商、内部运营 |
| 适用品牌 | 当前账号可用于哪些品牌或子品牌 |
| 最近检测 | Hermes 最近一次检测时间 |
| 最近发布 | 最近一次成功发布时间 |
| 操作 | 去登录、检测账号、复检、编辑适用品牌、停用 |

### 6.3 状态文案

| 状态 | 展示文案 | 用户动作 |
|---|---|---|
| unknown | 未检测 | 去登录 / 检测账号 |
| logged_in | 可发布 | 复检 / 编辑适用品牌 |
| logged_out | 未登录 | 去登录 |
| expired | 登录已失效 | 重新登录 |
| check_failed | 检测失败 | 查看原因 / 重试检测 |

## 7. 核心流程

### 7.1 首次登录检测

1. 用户点击平台卡片上的“去登录”。
2. 前端打开平台官方登录页。
3. 用户在浏览器中完成登录。
4. 用户回到系统点击“我已完成登录，检测账号”。
5. 后端创建 `AgentTask`，任务类型为 `account_login_check`。
6. Hermes 使用本机浏览器环境访问平台页面。
7. Hermes 判断是否已登录，并尽量读取账号名称。
8. 检测成功后更新 `loginStatus = logged_in`。
9. 检测失败时展示可操作原因，例如未登录、验证码未完成、平台风控、浏览器 profile 不一致。

### 7.2 发布前校验

发布计划执行前必须校验：

1. 目标品牌在 `usableBrandIds` 中。
2. 平台匹配。
3. `loginStatus = logged_in`。
4. `lastCheckedAt` 未超过有效期，例如 24 小时或 7 天，可配置。
5. Hermes 本地服务在线。

如果校验不通过：

1. 发布计划进入“待处理”或“账号需重新登录”。
2. 页面提示用户去“发布账号”完成重新登录或复检。
3. 不直接尝试发布，避免触发平台风控。

### 7.3 多品牌适用范围

首期只做轻量配置：

1. 发布账号默认只适用于当前品牌。
2. 用户可手动增加适用品牌或子品牌。
3. 服务商账号可选择多个服务品牌。
4. 品牌自有账号是否允许分配给服务商，由人工流程或平台审核控制，不在首期做复杂权限流。

## 8. 与 Hermes 的边界

系统负责：

1. 记录平台、账号名、登录状态和适用品牌。
2. 提供登录入口和检测按钮。
3. 创建 Hermes 检测任务和发布任务。
4. 根据检测结果更新账号状态。
5. 在发布前做账号可用性判断。

Hermes 负责：

1. 使用本机浏览器 profile 打开平台页面。
2. 判断当前平台是否已登录。
3. 读取可见账号名。
4. 执行文章发布、截图、链接回传。
5. 返回结构化成功或失败结果。

系统不负责：

1. 保存平台密码。
2. 保存完整 cookie 或 token 到业务数据库。
3. 绕过验证码、扫码、人机验证或平台风控。
4. 在非登录电脑上远程复用用户登录态。

## 9. 接口调整

当前 `/api/accounts` 可以继续保留，但接口语义建议逐步调整为发布账号。

| 方法 | 路径 | 说明 |
|---|---|---|
| GET | `/api/accounts?brandName=xxx` | 查询品牌可用发布账号，兼容旧接口 |
| POST | `/api/accounts/bind/start` | 打开平台登录流程，语义改为 login/start |
| POST | `/api/accounts/bind/confirm` | 用户确认已登录，触发 Hermes 检测 |
| POST | `/api/accounts/verify-agent` | 主动复检本机登录态 |
| POST | `/api/accounts/unbind` | 停用该发布账号或清除登录状态标记 |
| POST | `/api/accounts/update` | 更新账号备注、提供方、适用品牌 |

后续可新增更清晰接口：

| 方法 | 路径 | 说明 |
|---|---|---|
| GET | `/api/publish-accounts` | 查询发布账号 |
| POST | `/api/publish-accounts/:id/login/start` | 开始本机登录 |
| POST | `/api/publish-accounts/:id/login/check` | 检测本机登录态 |
| PATCH | `/api/publish-accounts/:id/scope` | 更新适用品牌 |
| GET | `/api/brands/:id/available-publish-accounts` | 查询品牌可用发布账号 |

## 10. 迭代拆分

### Phase 1：收敛命名与现有流程

目标：把“账号绑定”改成“发布账号”，但不重构底层。

任务：

1. 侧边栏 `账号绑定` 改为 `发布账号`。
2. 页面标题改为 `发布账号管理`。
3. 所有“授权”文案改为“登录 / 检测登录态”。
4. 顶部说明明确：需要在本机浏览器完成平台登录，Hermes 才能自动发布。
5. 保留现有 `/api/accounts` 和 `AccountBinding`。

验收：

1. 用户能理解自己要在本机登录平台账号。
2. 现有去授权、确认、复检、解绑流程仍能使用。
3. 文案不再暗示系统保存平台开户授权。

### Phase 2：增加发布可用性字段

目标：让账号状态真正服务发布链路。

任务：

1. `AccountBinding` 增加或映射 `loginStatus`、`providerType`、`localDeviceLabel`、`usableBrandIds`。
2. Hermes 检测结果写入登录状态和检测时间。
3. 发布计划执行前校验账号登录状态。
4. 内容发布和发布计划统一读取可用发布账号。

验收：

1. 未登录或登录失效账号不能被发布任务使用。
2. 检测成功账号可用于指定品牌发布。
3. 检测失败原因可在页面展示。

### Phase 3：多品牌与服务商轻量支持

目标：覆盖服务商代运营和集团多子品牌，但不做复杂资产池。

任务：

1. 账号详情支持编辑适用品牌或子品牌。
2. 增加提供方字段：品牌方、服务商、内部运营。
3. 服务商端资源账号只展示可发布平台、账号数量和检测状态。
4. 平台端可查看服务商账号可用性，但不展示敏感登录信息。

验收：

1. 一个服务商本机登录账号可服务多个品牌。
2. 一个集团运营账号可服务多个子品牌。
3. 品牌发布时只看到自己可用的发布账号。

### Phase 4：日志与异常处理

目标：减少发布失败时的排查成本。

任务：

1. 增加登录检测日志。
2. 增加发布使用记录。
3. 发布失败关联到账号、品牌、内容和 Hermes 任务。
4. 对账号失效、平台风控、验证码阻塞给出可读提示。

验收：

1. 每次检测都有结果记录。
2. 每次发布失败都能追溯到具体账号和失败原因。
3. 用户知道下一步应该重新登录、重试检测还是联系平台。

## 11. 验收场景

| 场景 | 操作 | 预期结果 |
|---|---|---|
| 首次登录 | 用户点击去登录并完成平台登录 | Hermes 检测成功，账号状态变为可发布 |
| 登录失效 | 平台 session 过期 | 复检失败，发布计划提示重新登录 |
| 服务商代运营 | 服务商电脑登录账号并分配给品牌 A/B | 品牌 A/B 发布时可选择该账号 |
| 子品牌发布 | 集团运营电脑登录账号并设置适用子品牌 | 只有被选中的子品牌可使用 |
| 发布前校验 | 账号未检测或检测过期 | 不执行发布，提示检测账号 |
| 平台风控 | Hermes 遇到验证码或异常登录 | 任务失败并提示用户手动处理 |

## 12. 风险与注意事项

1. 本模块依赖用户本机浏览器登录态，不是云端账号授权。
2. 同一个用户换电脑后，需要重新登录和检测。
3. 浏览器 profile 必须稳定，否则 Hermes 检测到的登录态可能和用户手动登录不一致。
4. 不应保存用户平台密码。
5. 不应在业务数据库保存完整 cookie 或 token。
6. 平台验证码、扫码、人机验证必须由用户完成。
7. 服务商代运营时，要在页面上明确“该账号由服务商本机环境提供发布能力”。

## 13. 推荐优先级

| 优先级 | 内容 | 原因 |
|---|---|---|
| P0 | `账号绑定` 改为 `发布账号` | 让用户理解真实动作是本机登录 |
| P0 | 文案从授权改为登录态检测 | 避免误解为 API 授权 |
| P0 | 发布前校验登录状态 | 保证 Hermes 发布成功率 |
| P1 | 适用品牌/子品牌 | 覆盖服务商和集团场景 |
| P1 | 检测日志和失败原因 | 方便排查 |
| P2 | 余额信息合并展示 | 余额不是登录态核心，可后置 |
