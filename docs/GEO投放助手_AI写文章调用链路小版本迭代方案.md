# GEO 投放助手：AI 写文章调用链路小版本迭代方案

版本：v1.3.1 文章生成专项  
日期：2026-06-05  
关联文档：`GEO投放助手_Hermes连调前Web端功能补齐迭代计划.md`  
开发口径：本小版本只定义“AI 写文章”的执行边界和 Web 端补齐点；不并入大文档，不要求真实 Hermes 连调，不改变 Hermes 负责诊断/发布留证的主线

---

## 1. 检查结论

AI 写文章不建议直接全量调用 Hermes。推荐拆成两层：

```text
Hermes GEO 技能
  负责：快速检测、专业审计、Schema、llms.txt、可引用性分析、报告、发布留证
        ↓
Web 端 AI 写文章
  负责：读取 Hermes 报告 + 品牌资料 + 知识库 + 关键词 + 禁用词，生成可编辑文章
        ↓
内容库人工确认
        ↓
需要本机发布时，再调用 Hermes 发布 / 截图 / 留证
```

这样分工更稳定：

1. Hermes 适合长任务、网页读取、文件生成、自动化执行、截图和证据链。
2. Web 端 AI 更适合文章、FAQ、问答、测评稿等内容生成。
3. 文章生成结果需要进入内容库供人工编辑，不应直接自动发布。
4. 发布动作风险高，应继续由 Hermes 在用户确认后执行并留证。

---

## 2. 当前缺陷

| 缺陷 | 当前问题 | 补齐方向 | 优先级 |
|---|---|---|---|
| 仍是 Mock 文章 | `DirectModelExecutor.generateArticles` 固定生成 mock 文案 | 接入 Web 端 AI 文章生成服务 | P0 |
| 没读取 Hermes 报告 | 文章生成没有 `geoReportId` 输入 | 支持从报告 findings/actionPlan/contentGap 生成文章 | P0 |
| 没读取知识库正文 | 前端传 `knowledgeCategories`，后端未取 `KnowledgeEntry` | 后端按分类读取品牌知识库 | P0 |
| 禁用词不阻断 | 只传 `negativeKeywords`，生成后未校验 | 生成后做禁用词和风险词检测 | P0 |
| 预览和提交混淆 | “预览摘要”和“提交任务”都打开同一确认弹窗 | 拆成摘要预览和正式提交 | P1 |
| 文章质检缺失 | 没有事实、可引用性、平台风格检查 | 增加生成后质检结果 | P1 |
| 发布链路分叉 | `publish-draft` 和 `hermes-publish` 两套路径口径不同 | 统一内容库发布入口 | P1 |

## 3. 产品边界

### 3.1 谁调用 Hermes

| 场景 | 执行方 | 说明 |
|---|---|---|
| GEO 快速检测 | Hermes | 使用 `geo-quick-start` |
| GEO 专业审计 | Hermes | 使用 `geo-audit` 和专项技能 |
| Schema / llms.txt | Hermes | 生成机器可读资产 |
| 内容可引用性分析 | Hermes | 分析页面或文章段落 |
| AI 写文章 | Web 端 AI | 读取 Hermes 报告和品牌资料生成内容 |
| 文章改写 | Web 端 AI | 适合快速生成多个版本 |
| 自动发布 | Hermes | 用户确认后操作本机浏览器并留证 |
| 发布截图 / 链接回传 | Hermes | 写入发布记录和证据链 |

### 3.2 文章生成输入来源

文章生成必须聚合这些上下文：

| 来源 | 数据 | 用途 |
|---|---|---|
| 品牌资料 | 行业、城市、服务、描述、竞品、禁用词 | 保证事实一致 |
| 关键词库 | 品牌词、行业词、长尾词、本地词 | 控制覆盖方向 |
| 知识库 | 企业介绍、产品服务、FAQ、案例、资质 | 提供真实素材 |
| Hermes 报告 | findings、actionPlan、contentGap、scores、platformMatrix | 决定写什么内容 |
| 用户配置 | 平台、数量、方向、语气、营销强度、字数 | 决定输出格式 |

## 4. 发布端页面调整

### 4.1 生成 GEO 文章页

#### 页面目标

让用户能选择“按品牌资料生成”或“根据 Hermes GEO 报告生成”，并清楚看到文章是否引用了报告结论。

#### 线框位置

```text
┌────────────────────────────────────────────────────────────┐
│ 生成 GEO 文章                                              │
├────────────────────────────────────────────────────────────┤
│ 品牌：云杉口腔                                             │
│ 生成来源                                                   │
│ [按品牌资料生成] [根据 GEO 报告生成] ◄─ P0 新增             │
├──────────────────────────────────────┬─────────────────────┤
│ 写作配置                             │  右侧摘要           │
│ 关联报告：云杉口腔 · 专业审计 #xxxx  │  报告缺口：8 项     │
│ 目标平台：小红书 / 知乎 / 公众号     │  重点 finding：     │
│ 内容方向：FAQ / 测评 / 问答 / 种草   │  - Schema 缺失      │
│ 关键词：南京种植牙、隐形矫正         │  - FAQ 不足         │
│ 知识库引用：企业介绍/FAQ/案例        │  禁用词：3 个       │
│ 数量 / 字数 / 语气 / 营销强度        │                     │
│                                      │  [预览输入摘要]     │
│ [提交 Web AI 写作任务]               │  [查看报告]         │
└──────────────────────────────────────┴─────────────────────┘
```

#### 功能点

| 功能 | 说明 |
|---|---|
| 生成来源 | 默认按品牌资料生成；可选择最近一份 Hermes 报告 |
| 报告选择 | 展示报告类型、分数、缺口数、创建时间 |
| 报告摘要 | 展示 contentGap、top findings、actionPlan |
| 输入预览 | 只展示将提交给 Web AI 的上下文，不创建任务 |
| 正式提交 | 创建 `article_generation` 或 `article_rewrite` 任务 |
| 生成后质检 | 展示禁用词、事实缺失、可引用性提示 |

### 4.2 内容库文章详情

#### 页面目标

生成后的文章必须能追溯来源：来自哪个 Hermes 报告、用了哪些知识库、有哪些质检风险。

#### 线框位置

```text
┌────────────────────────────────────────────────────────────┐
│ 内容库 > 文章详情                                          │
├──────────────────────────────┬─────────────────────────────┤
│ 文章正文                     │  来源与质检                 │
│ 标题                         │  来源报告：专业审计 #xxxx   │
│ 正文                         │  引用知识库：FAQ/案例       │
│                              │  覆盖关键词：5 个           │
│                              │  禁用词检测：通过/不通过    │
│                              │  GEO 可引用性：72           │
│                              │                             │
│ [保存修改] [生成改写版本]    │  [根据报告再生成一篇]       │
│ [确认入发布计划]             │  [回到报告]                 │
└──────────────────────────────┴─────────────────────────────┘
```

#### 功能点

1. 显示 `geoReportId` / `sourceReportTitle`。
2. 显示使用的知识库分类和关键词。
3. 显示禁用词检测结果。
4. 显示质检建议。
5. 允许从同一报告继续生成更多文章。

## 5. 接口与数据补充

### 5.1 文章生成任务输入

沿用 `POST /api/agent-tasks`，但扩展 `article_generation` 输入：

```json
{
  "type": "article_generation",
  "title": "云杉口腔 · 小红书 GEO 文章生成",
  "brandName": "云杉口腔",
  "input": {
    "source": "geo_report",
    "geoReportId": "report-id",
    "targetPlatform": "小红书",
    "contentDirection": "FAQ",
    "tone": "自然",
    "marketingIntensity": 20,
    "keywords": ["南京种植牙", "隐形矫正推荐"],
    "negativeKeywords": ["绝对安全", "排名第一"],
    "knowledgeCategories": ["intro", "product", "faq", "case"],
    "quantity": 3,
    "wordCount": 800,
    "qualityChecks": ["forbidden_words", "fact_coverage", "geo_citability"]
  }
}
```

后端处理要求：

1. 如果有 `geoReportId`，读取报告详情。
2. 读取品牌资料。
3. 读取关键词库。
4. 按 `knowledgeCategories` 读取 `KnowledgeEntry`。
5. 合并成 Web AI prompt。
6. 生成文章后做质检。
7. 写入 `ContentBatch` 和 `ContentItem`。

### 5.2 ContentItem 建议扩展

短期可先放 JSON 字段，正式版建议扩展：

| 字段 | 说明 |
|---|---|
| `sourceType` | `manual`、`brand_profile`、`geo_report` |
| `sourceReportId` | 来源 GEO 报告 |
| `sourceTaskId` | 来源 AgentTask |
| `usedKnowledgeJson` | 使用的知识库分类和条目 |
| `qualityChecksJson` | 禁用词、事实覆盖、可引用性检测 |
| `generationMetaJson` | 模型、字数、平台、prompt 摘要 |

### 5.3 质检输出

建议写入 task output：

```json
{
  "articles": [],
  "qualityChecks": {
    "forbiddenWords": {
      "passed": true,
      "hits": []
    },
    "factCoverage": {
      "passed": true,
      "missing": ["医生资质编号"]
    },
    "geoCitability": {
      "score": 72,
      "suggestions": ["增加可直接摘录的短答案段落"]
    }
  }
}
```

## 6. 迭代拆分

### P0：真实写作输入闭环

| 编号 | 功能 | 说明 |
|---|---|---|
| P0-01 | 文章生成支持 `geoReportId` | 根据 Hermes 报告生成文章 |
| P0-02 | 后端聚合品牌资料和知识库 | 不再只传分类名 |
| P0-03 | 接入 Web 端 AI 生成服务 | 替换 Mock 文章生成 |
| P0-04 | 禁用词检测 | 生成后阻断或标红风险 |
| P0-05 | 内容库记录来源报告 | 文章可追溯到报告和任务 |

### P1：体验和质检

| 编号 | 功能 | 说明 |
|---|---|---|
| P1-01 | 拆分“预览摘要”和“提交任务” | 避免按钮行为混淆 |
| P1-02 | 文章质检面板 | 展示事实覆盖、可引用性、平台风格 |
| P1-03 | 根据同一报告继续生成 | 从内容库/报告详情再次生成文章 |
| P1-04 | 统一发布入口 | 内容库发布统一走 `publish-draft`，Hermes 只负责确认后的发布执行 |

### P2：Hermes 辅助增强

| 编号 | 功能 | 说明 |
|---|---|---|
| P2-01 | 文章可引用性复检 | 写完后可调用 Hermes `geo-citability` 复检 |
| P2-02 | 发布后证据回填 | Hermes 发布成功后回填截图、链接、平台提示 |
| P2-03 | 月度复盘关联 | 已发布文章进入 `geo-compare` 的动作完成度 |

## 7. 验收标准

1. 用户可以选择“根据 GEO 报告生成文章”。
2. 提交写作任务时，后端能读取报告、品牌资料、关键词、知识库和禁用词。
3. Web 端 AI 生成结果写入内容库，不直接发布。
4. 文章详情能看到来源报告、使用素材和质检结果。
5. 禁用词命中时必须提示，严重命中不允许进入发布确认。
6. 发布动作仍由用户确认后触发 Hermes，不由写作任务自动发布。
7. “预览摘要”不创建任务，“提交任务”才创建 AgentTask。

## 8. 风险与评审问题

| 风险 | 说明 | 建议 |
|---|---|---|
| 报告内容太长 | 全量塞进 prompt 成本高 | 只取 top findings、contentGap、actionPlan |
| 知识库质量不足 | 文章可能仍泛泛而谈 | 缺知识库时提示补资料 |
| 禁用词只做字符串匹配 | 变体风险漏检 | P0 先字符串，P1 加语义风险检测 |
| Web AI 与 Hermes 口径不一致 | 报告建议和文章输出可能脱节 | prompt 中强制引用报告问题和行动计划 |
| 自动发布误触 | 写作完成后不应自动发第三方平台 | 写作与发布拆成两个确认动作 |

待评审问题：

1. Web 端 AI 首期使用 MiniMax，还是统一走 Agent 云算力接口。
2. `ContentItem` 是新增 JSON 字段，还是先把来源信息写入 `structure` / task output。
3. 禁用词命中是阻断保存，还是允许保存但阻断发布。
4. 文章质检是否首期只做禁用词，还是同时做可引用性评分。

---

## 9. 一句话结论

AI 写文章应作为 Web 端 AI 能力实现，输入来自 Hermes GEO 报告和品牌知识库；Hermes 不负责日常文章生成，只负责审计、资产检查、自动发布和证据留存。这样链路更短、体验更稳，也更容易把文章沉淀到内容库和订单交付。
