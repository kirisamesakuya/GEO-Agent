# GEO 投放助手：Hermes 结果通知确认流迭代方案

版本：v1.0  
日期：2026-06-06  
适用范围：发布端品牌资料提取、AI 挖词，以及后续同类 Hermes / Agent 结构化产物确认入库能力  
开发口径：本方案先统一 Web 端任务状态、通知承载、用户确认和后端入库职责；Hermes 技能真实输出沿用现有 AgentTask.output 承载，不要求重做 Hermes 执行器。

---

## 1. 方案结论

该方案可行，且建议实施。

当前 `AI 提取品牌资料`、`AI 挖词` 等功能存在明显的页面私有结果处理问题：每个页面自己提交任务、自己轮询、自己解释输出、自己决定是否入库。随着 Hermes 技能增加，这种模式会造成重复代码、结果状态不一致、用户离开页面后体验断裂，以及 AI 结果未经统一确认就写入业务数据。

推荐将同类功能升级为：

```text
页面提交任务
  ↓
AgentTask / Hermes 异步执行
  ↓
任务完成后生成通知
  ↓
用户在通知或任务详情中预览结果
  ↓
用户确认后由后端统一入库
```

核心原则：

1. Hermes / Agent 任务统一创建、统一执行、统一通知。
2. 页面不再承担长期等待和结果落库职责。
3. AI 生成的结构化业务数据，必须经用户确认后再入库。
4. 报告、文章、发布记录等已有专属结果页的能力，只通知完成，不强制改成通知入库。

## 3. 目标体验

### 3.1 用户不必等在原页面

用户点击 `AI 提取品牌资料` 或 `开始 AI 挖词` 后，页面立即显示任务已提交。用户可以继续编辑、切换页面或离开当前功能区。

### 3.2 通知承载完整反馈

任务完成后，通知中心出现一条明确状态：

```text
AI 挖词完成，待确认入库
已生成 24 个候选关键词，请确认后写入关键词库。
```

用户点击后进入确认视图，可以预览结果、确认入库、忽略或重新生成。

### 3.3 后端统一执行入库

用户确认后，前端只调用确认接口。实际写入品牌资料、关键词库等动作由后端根据 `task.type` 分发执行，避免页面复制业务规则。

## 5. 功能范围

### 5.1 P0 必做

| 功能 | 说明 |
|---|---|
| 品牌资料提取改为待确认 | `brand_extract` 成功后不直接覆盖品牌资料 |
| AI 挖词改为待确认 | `keyword_mining` 成功后不依赖页面 suggestions 入库 |
| 新增结果确认接口 | `POST /api/agent-tasks/:id/confirm-result` |
| 新增结果忽略接口 | `POST /api/agent-tasks/:id/reject-result` 或 `dismiss-result` |
| 通知中心展示待确认状态 | 通知卡片展示“待确认入库” |
| 任务详情展示结构化预览 | 品牌资料、关键词分组结果不只展示 JSON |
| 原页面提交态优化 | 提交任务后提示可离开，并提供查看进度入口 |

### 5.2 P1 可选增强

| 功能 | 说明 |
|---|---|
| 品牌资料字段差异对比 | 展示当前值 / AI 建议值 |
| 关键词勾选入库 | 用户可选择部分候选词入库 |
| 通知抽屉预览 | 不进入任务详情也能快速确认 |
| 重跑参数复用 | 从通知或任务详情一键重新生成 |
| 结果确认审计日志 | 记录确认人、确认时间、入库条数 |

### 5.3 暂不纳入

| 功能 | 原因 |
|---|---|
| 文章生成强制通知确认入库 | 内容库已是结果承载页，通知只需跳转 |
| GEO 报告强制通知确认入库 | 报告本身就是业务结果，通知只需提醒 |
| Hermes 发布改为确认入库 | 发布是执行动作，结果应写发布记录；通知处理异常和状态 |
| 排名监控结果确认 | 监控采样应自动入库，异常才通知 |

## 6. 后端改动

### 6.1 AgentTask 成功处理

文件：`server/agent/task-success.ts`

#### brand_extract

当前逻辑：

```text
任务成功
  ↓
output.profile 存在
  ↓
直接 saveBrandProfile
```

目标逻辑：

```text
任务成功
  ↓
output.profile 存在
  ↓
不直接 saveBrandProfile
  ↓
updateAgentTask:
    needsReview=true
    reviewCategory='result_confirm_required'
    output.confirmationType='brand_profile'
```

#### keyword_mining

新增逻辑：

```text
任务成功
  ↓
output.suggestions 存在
  ↓
updateAgentTask:
    needsReview=true
    reviewCategory='result_confirm_required'
    output.confirmationType='keyword_suggestions'
```

### 6.2 结果确认服务

建议新增文件：

```text
server/services/agent-result-confirmation.service.ts
```

职责：

| 方法 | 说明 |
|---|---|
| `confirmAgentTaskResult(taskId, input)` | 按任务类型确认入库 |
| `rejectAgentTaskResult(taskId, reason)` | 标记结果已忽略 |
| `previewAgentTaskResult(task)` | 给前端返回结构化预览摘要 |

任务类型分发：

| task.type | 确认动作 |
|---|---|
| `brand_extract` | 调 `saveBrandProfile` |
| `keyword_mining` | 调 `bulkCreateKeywords` |

确认后更新任务：

```text
needsReview=false
reviewCategory=null
output.confirmedAt=ISO_TIME
output.confirmResult={ type, count, target }
```

忽略后更新任务：

```text
needsReview=false
reviewCategory='result_rejected'
output.rejectedAt=ISO_TIME
output.rejectReason=reason
```

### 6.3 API 路由

文件：`server/routes/agent-tasks.ts`

新增接口：

```text
GET  /api/agent-tasks/:id/result-preview
POST /api/agent-tasks/:id/confirm-result
POST /api/agent-tasks/:id/reject-result
```

#### confirm-result 请求示例

品牌资料：

```json
{
  "confirmedBy": "merchant"
}
```

关键词：

```json
{
  "confirmedBy": "merchant",
  "selectedTerms": ["南京种植牙", "儿童齿科推荐"],
  "groupOverrides": {
    "南京种植牙": "geo"
  }
}
```

### 6.4 创建任务时补齐 brandName

文件：`server/routes/brand.ts`

`/api/extract-brand` 需要接收并写入 `brandName`：

```text
body.brandName
  ↓
createAgentTask({ brandName })
```

否则任务完成后通知无法稳定挂到对应品牌。

### 6.5 通知事件增强

文件：`server/lib/publisher-notification-events.ts`

对待确认类任务使用不同文案：

| task.type | 通知标题 | actionView |
|---|---|---|
| `brand_extract` | 品牌资料已提取，待确认入库 | `agent_tasks` |
| `keyword_mining` | AI 挖词完成，待确认入库 | `agent_tasks` |

通知仍可复用 `refId=task.id`，无需 P0 改 Prisma 表。

## 12. 验收标准

### 12.1 品牌资料提取

1. 用户在品牌资料页点击 `AI 提取品牌资料` 后，页面提示任务已提交。
2. 用户离开该页面后，任务仍可继续执行。
3. 任务完成后消息通知出现 `品牌资料已提取，待确认入库`。
4. 未确认前，品牌资料库不被 AI 结果覆盖。
5. 用户确认后，品牌资料写入成功。
6. 用户忽略后，品牌资料不变，任务显示已忽略。

### 12.2 AI 挖词

1. 用户在关键词库点击 `开始 AI 挖词` 后，页面提示任务已提交。
2. 任务完成后消息通知出现 `AI 挖词完成，待确认入库`。
3. 未确认前，关键词库不新增候选词。
4. 用户确认后，候选词写入关键词库。
5. 重复关键词自动跳过，不报错中断。
6. 用户忽略后，关键词库不变化。

### 12.3 通知与任务详情

1. 通知中心能筛选 `待确认`。
2. 点击通知可进入对应任务详情。
3. 任务详情展示结构化预览，而不是只显示 JSON。
4. 确认成功后通知和任务详情状态刷新。
5. 失败任务仍可走原有重试流程。

## 13. 风险与处理

| 风险 | 影响 | 处理 |
|---|---|---|
| 用户已读通知但未确认 | 结果长期悬挂 | 增加 `待确认` 筛选，不依赖未读 |
| AI 输出结构不稳定 | 预览和入库失败 | 确认服务做 schema 容错和错误提示 |
| 品牌资料被旧逻辑直接保存 | 破坏确认流程 | P0 必须先改 `task-success.ts` |
| 关键词重复 | 入库报错 | 继续复用唯一约束并跳过重复 |
| 通知卡片直接确认误操作 | 写入错误数据 | P0 只允许进入详情确认，P1 再做快捷确认 |

## 14. 推荐落地顺序

优先做一条完整闭环，不要同时铺太多技能。

推荐顺序：

1. 先改 `keyword_mining`，因为它当前已经是“候选结果后一键入库”，迁移成本低。
2. 再改 `brand_extract`，因为它涉及覆盖品牌主资料，确认价值更高。
3. 最后把模式抽象成通用 `AgentResultConfirmation` 服务，供知识库抽取、素材标签等功能复用。

最终目标不是让通知替代所有结果页，而是让通知成为“异步任务完成后的统一处理入口”。
