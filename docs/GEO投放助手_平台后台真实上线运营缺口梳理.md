# GEO 投放助手：平台后台真实上线运营缺口梳理

版本：v0.1  
日期：2026-06-08  
范围：基于当前发布端、接单端、平台端已落地功能与 Prisma 数据模型，梳理平台后台距离真实上线运营仍缺少的功能。  
结论口径：不以“页面有入口 / mock 数据可展示”为上线完成标准，而以“运营可发现问题、处理问题、追踪责任、形成审计与财务闭环”为标准。

---

## 1. 总体结论

当前平台后台已经具备较完整的运营中台雏形，包含平台驾驶舱、商家/组织认证、内容与发布监管、排名监控运营、Agent/Hermes 监控、订单监管、网站订单、风险中心、资金算力、结算、消息通知、角色权限、系统配置、审计日志、运营报表等模块。

但距离真实上线运营仍有 8 类核心缺口：

1. 认证与平台权限仍保留 Demo 机制，后台角色可由前端请求头/参数推断，不能直接用于生产。
2. 注册用户、组织、接单方、平台成员的真实账号生命周期不完整，缺少注册、登录、找回、实名/企业归属、成员邀请和账号风控。
3. 充值账户与资金账户体系不完整，当前更接近人工余额记录，缺少真实充值、支付流水、开票、对账、退款和账户安全。
4. 平台发布账号运营被显式下线，发布账号、授权失效、自动发布失败无法在后台形成独立运营闭环。
5. 内容与发布、排名监控、通知、报表等页面以“可查看”为主，缺少可执行的运营动作和动作结果追踪。
6. 接单方资源审核与履约评级被前端隐藏或依赖推算，尚未形成可用于真实派单的可信能力体系。
7. 订单履约、争议、返修、结算已有基础动作，但缺少 SLA、证据链、沟通记录、赔付/扣罚、财务对账。
8. 风控中心由若干异常聚合而来，缺少统一工单生命周期、责任人、处置记录、升级规则。
9. 运营支撑能力不足：告警、导出、搜索、分页、数据权限、监控、备份、生产配置灰度等仍需补齐。

## 3. P0：真实上线前必须补齐

### 3.1 生产认证与平台权限闭环

当前问题：

- `AUTH_MODE=demo` 仍是默认模式。
- 平台角色可通过 `X-Platform-Role`、query、body 推断。
- `PlatformRolesView` 的成员列表为固定 mock 数据，不能真实增删成员、停用成员、调整角色。
- 部分接口仍存在权限校验不一致，例如网站订单相关接口有些没有显式 `requirePlatformPermission`。

必须补齐：

1. 生产默认启用 `AUTH_MODE=session`，未登录后台请求统一 401。
2. 平台角色只允许来自 `User` / `Session` / `PlatformUserRole`，禁止信任前端传入角色。
3. 后台成员管理支持邀请、停用、角色调整、最近登录、登录失败锁定。
4. 所有 `/api/platform/*` 接口统一做角色和操作权限校验。
5. 敏感动作强制填写原因，并写入审计日志。

建议验收：

- 删除所有前端传 role 后，平台端仍能按登录用户权限正常工作。
- 普通客服账号无法调用资金调整、配置写入、商家停用、订单改派等接口。
- 每次角色变更都能在审计日志中查到操作者、对象、变更前后内容。

### 3.2 注册用户与账号生命周期

当前问题：

- 数据模型已有 `User`、`Session`、`ProviderUser`、`PlatformUserRole`、`OrganizationMember`，但前端尚未形成真实注册/登录/成员邀请流程。
- 当前发布端、接单端、平台端仍大量依赖 Demo 用户、品牌名、接单方 ID 或本地角色切换。
- 缺少账号安全能力：手机号/邮箱验证、密码找回、账号冻结、登录日志、异常登录提醒。
- 商家用户、组织、品牌、接单方、平台成员之间的归属关系需要后台可视化管理。

必须补齐：

1. 注册与登录：手机号/邮箱注册、验证码、密码登录、退出登录、找回密码。
2. 商家开户注册：创建组织、创建默认品牌、提交组织认证、邀请成员。
3. 接单方开户注册：创建接单方主体、绑定用户、提交入驻申请、审核通过后可接单。
4. 平台成员管理：邀请成员、分配角色、停用/恢复账号、重置密码或强制退出。
5. 账号安全：登录日志、Session 管理、异常登录锁定、账号冻结、敏感操作二次验证。
6. 用户后台检索：按手机号、邮箱、姓名、组织、品牌、接单方、角色搜索用户。

建议新增或增强对象：

| 对象 | 说明 |
|---|---|
| `LoginLog` | 登录时间、IP、UA、结果、失败原因 |
| `VerificationCode` | 手机/邮箱验证码，含场景和过期时间 |
| `PasswordResetToken` | 找回密码或重置密码凭证 |
| `UserSecurityEvent` | 冻结、解冻、密码修改、异常登录等安全事件 |
| `PlatformInvitation` | 平台成员或组织成员邀请记录 |

建议验收：

- 新商家可以从注册到创建组织/品牌，再完成认证提交。
- 新接单方可以从注册到提交入驻，再由平台审核通过。
- 平台管理员可以停用某个用户，停用后该用户所有端都无法继续操作。
- 任意用户登录、登出、失败登录、角色变更都能被平台追踪。

### 3.3 充值账户与资金账户体系

当前问题：

- 当前已有 `BudgetAccount`、`BudgetLedger`、`BudgetDepositRequest`、`AiCredits`，但更接近 Demo/人工记账。
- 前端尚未做真实充值账户、充值入口、支付渠道、发票和对账。
- 账户余额、冻结金额、AI 算力、订单结算之间的资金关系需要明确账户体系。
- 充值审核、余额调整、AI 点数调整虽然有后台动作，但缺少支付流水、凭证、余额前后、操作人和财务审核状态。

必须补齐：

1. 商家充值账户：账户余额、可用余额、冻结金额、累计充值、累计消耗、退款中金额。
2. 充值流程：创建充值单、选择支付/线下转账、上传凭证、平台审核、入账。
3. 支付流水：外部交易号、支付渠道、支付状态、到账时间、失败原因。
4. 资金流水：充值、冻结、扣款、释放、退款、人工调整、赠送、纠错，每笔记录余额前后。
5. AI 算力账户：购买、赠送、消耗、回退、过期、同步失败记录。
6. 发票与对账：开票信息、发票申请、发票状态、月度对账单。
7. 账户安全：大额充值/调整二次确认、负余额拦截、冻结金额不能大于余额。

建议账户分层：

| 账户 | 用途 |
|---|---|
| `CashAccount` / 增强 `BudgetAccount` | 商家人民币充值余额 |
| `CashLedger` / 增强 `BudgetLedger` | 商家资金流水，记录余额前后和外部凭证 |
| `PaymentTransaction` | 支付渠道或线下转账流水 |
| `InvoiceRequest` | 发票申请和开票状态 |
| `CreditAccount` / 增强 `AiCredits` | AI 算力账户 |
| `CreditLedger` | AI 点数购买、消耗、赠送、回退流水 |

建议验收：

- 商家可以看到充值账户余额、冻结、消耗和每笔流水。
- 平台可以审核充值凭证，审核通过后自动生成资金流水并更新余额。
- 订单创建时冻结预算，订单完成时扣款，取消/争议退款时释放或回滚。
- 财务可以按月导出充值、消耗、退款、结算和开票数据。

### 3.4 发布账号运营中心

当前问题：

- `PLATFORM_PUBLISH_ACCOUNT_OPS_ENABLED=false`，代码注释明确“本期平台不运营商家发布账号”。
- 数据模型已有 `AdAccount`、`AdAccountAuthSession`、`AdAccountUsageLog`，但后台无独立页面和接口闭环。
- 发布失败只能在内容监管或 Agent 人工标记中间接看到，无法按账号维度处理授权失效、登录异常、权限不足。

必须补齐：

1. 发布账号列表：平台、账号、归属、授权状态、风险状态、过期时间、最近检测时间。
2. 授权异常队列：未授权、授权过期、登录失败、权限不足、账号禁用。
3. 账号详情：授权会话、使用记录、关联发布计划、发布记录、Agent 任务、本地自动化证据。
4. 运营动作：通知商家重新授权、暂停账号、恢复账号、触发检测、转人工发布、标记可重试。
5. 审计与通知：每个账号状态变更、通知、重试都写入 `AuditLog` 和商家通知。

建议接口：

| 接口 | 说明 |
|---|---|
| `GET /api/platform/ad-accounts` | 发布账号列表 |
| `GET /api/platform/ad-accounts/:id` | 账号详情 |
| `POST /api/platform/ad-accounts/:id/check` | 触发账号检测 |
| `POST /api/platform/ad-accounts/:id/notify-reauth` | 通知重新授权 |
| `POST /api/platform/ad-accounts/:id/status` | 暂停/恢复/人工修正 |

### 3.5 内容与发布监管处置闭环

当前问题：

- 页面已有“重试发布”“转人工”按钮，但当前视图内未看到对应后端动作落地。
- `PublishRecord` 只有 `status`、`publishedUrl`、`errorCode`、`reviewCategory`，缺少失败归因、处理人、处理状态、处理备注。
- 平台无法将内容风险、账号风险、自动化风险和商家通知串成闭环。

必须补齐：

1. 发布失败归因：账号授权、平台限制、内容违规、自动化异常、网络/环境、未知错误。
2. 发布记录处理状态：待处理、已通知、可重试、已重试、转人工、已忽略、已解决。
3. 内容审核动作：标记风险、要求改写、下架/暂停发布、放行。
4. 发布计划动作：暂停、恢复、跳过本次、改执行时间、改目标账号。
5. 发布记录与 `AgentTask`、`LocalAutomationRun`、`AdAccountUsageLog` 双向互链。

建议数据补充：

| 对象 | 字段 |
|---|---|
| `PublishRecord` | `failureReason`、`handledStatus`、`handledBy`、`handledAt`、`handledNote` |
| `PublishJob` | `lockedBy`、`lockedAt`、`nextRetryAt`、`maxAttempts` |
| `ContentItem` | `riskStatus`、`reviewStatus`、`reviewNote` |

### 3.6 接单方可信资源与派单依据

当前问题：

- `resource_review` 和 `fulfillment_rating` 在前端被隐藏。
- `ProviderAsset` 只有标题、类型、URL、备注，没有审核状态、可见性、附件证明、平台账号指标。
- `ProviderPricingRule` 没有审核状态。
- 履约评分由历史订单临时计算，没有沉淀到 Provider 风险等级，也没有进入派单/改派决策。

必须补齐：

1. 接单方资源审核正式开放，至少支持案例、账号、截图、报价、能力标签审核。
2. 未审核或驳回资源不得进入任务推荐和派单候选展示。
3. 派单/改派弹窗展示候选接单方的能力、报价区间、准时率、返修率、争议率、近期负载。
4. 接单方风险等级沉淀到数据表，支持人工冻结接单资格。
5. 资源变更、能力变更、报价变更需要重新审核并保留历史版本。

建议数据补充：

| 对象 | 字段 |
|---|---|
| `ProviderAsset` | `reviewStatus`、`reviewNote`、`visibility`、`platform`、`metricsJson` |
| `ProviderPricingRule` | `reviewStatus`、`reviewNote` |
| `Provider` | `score`、`riskLevel`、`suspendedReason`、`suspendedAt` |
| 新增 `ProviderCapabilityReviewLog` | 记录能力/资源审核历史 |

### 3.7 订单履约、争议与 SLA

当前问题：

- 订单状态流已有，但缺少 SLA、交付标准模板、验收倒计时、逾期自动提醒。
- 返修与争议数据较轻，缺少证据、责任认定、赔付/扣罚。
- 平台结案争议时直接把订单更新为 completed，真实运营中还需要支持退款、部分验收、取消、扣罚等结果。

必须补齐：

1. 订单 SLA：派单 SLA、交付 SLA、验收 SLA、返修 SLA、争议处理 SLA。
2. 交付证据链：链接、截图、附件、草稿、最终稿、修改记录、验收记录不可覆盖。
3. 争议工单：发起方、诉求、证据、平台处理人、结论、赔付/扣罚、结案时间。
4. 订单结案结果：完成、取消、部分结算、退款、扣罚、重派。
5. 自动提醒：即将超时、已超时、返修未处理、验收超时。

建议新增对象：

| 对象 | 说明 |
|---|---|
| `OrderSlaEvent` | 记录 SLA 节点和超时状态 |
| `OrderDispute` | 独立争议工单 |
| `OrderEvidence` | 交付、返修、争议证据统一表 |
| `OrderPenalty` | 扣罚/赔付记录 |

### 3.8 资金、结算与财务对账

当前问题：

- 本节是对 3.3 充值账户的下游补充，重点覆盖接单方提现、订单结算和平台财务对账。
- 充值、提现、结算主要是人工状态推进。
- 没有真实支付流水、打款流水、发票、对账单、退款。
- `BudgetLedger` 只记录金额变化，缺少余额前后、操作人、交易凭证、外部流水号等财务审计字段。

必须补齐：

1. 入账：收款凭证、外部流水号、审核人、审核备注、驳回原因。
2. 冻结/释放：每笔订单冻结、释放、扣款要能追踪到订单和余额前后。
3. 结算：结算批次、批量打款、打款凭证、收款主体、税务/发票状态。
4. 退款/扣罚：退款申请、审核、执行、资金回滚。
5. 对账：按日/月导出商家资金、平台收入、接单方应付、已付、未付。

建议验收：

- 任意订单可以追溯：商家入账 -> 预算冻结 -> 订单完成/取消 -> 释放/扣款 -> 接单方结算。
- 财务可以导出某月所有应收、应付、已收、已付和异常差异。

## 4. P1：上线初期建议紧随补齐

### 4.1 风险中心升级为工单系统

当前风险中心主要由订单、Agent、资金异常聚合，缺少工单状态。

建议补齐：

1. 风险工单状态：待分派、处理中、等待外部、已解决、已忽略。
2. 责任人、协作人、优先级、SLA、处理备注。
3. 一键跳转源对象，并支持从源对象回看工单。
4. 重复风险合并、升级规则、超时提醒。

### 4.2 排名监控运营动作

当前排名运营可查看计划和采样，但缺少处置。

建议补齐：

1. 暂停/恢复计划。
2. 立即执行采样。
3. 修改周期与目标平台。
4. 异常生成修复任务或内容订单。
5. 异常确认、忽略、持续观察。

### 4.3 消息通知中心生产化

当前只有固定模板和站内通知记录。

建议补齐：

1. 模板管理：新增、编辑、启停、变量校验、版本记录。
2. 发送任务：目标人群、触发条件、发送状态、失败重试。
3. 多端通知：商家端、接单端、平台端站内信统一模型。
4. 多渠道预留：短信、邮件、企业微信/飞书。
5. 已读/点击/处理转化追踪。

### 4.4 Agent 与 Hermes 运营监控增强

建议补齐：

1. Agent 队列和执行器健康：排队时长、执行时长、失败率、重试次数。
2. 成本与额度：每次模型调用、Hermes 调用、AI 点数消耗。
3. 自动化证据多条记录：截图、页面链接、平台提示、日志文件。
4. 失败分类：输入不完整、模型失败、平台限制、账号失效、自动化环境异常。
5. 告警：连续失败、某 Skill 成功率下降、Hermes 不健康。

### 4.5 系统配置生产化

建议补齐：

1. 配置分组：平台规则、预算规则、Skill 路由、模型、通知、风控。
2. 草稿/发布机制：编辑草稿、审批、发布、回滚。
3. 敏感配置脱敏展示。
4. 配置变更影响范围提示。
5. 配置灰度：按品牌、平台、任务类型启用。

## 6. 建议开发优先级

### 第一阶段：生产安全底座

1. 切换并固化生产认证与平台权限。
2. 统一 `/api/platform/*` 权限校验。
3. 后台成员与角色真实管理。
4. 敏感操作审计补齐 before/after、操作者、原因。

### 第二阶段：发布治理闭环

1. 发布账号运营中心。
2. 内容与发布监管动作落地。
3. 发布失败归因、通知、重试、转人工闭环。
4. Agent/Hermes 自动化证据增强。

### 第三阶段：接单方与订单履约闭环

1. 接单方资源审核正式开放。
2. 派单候选人能力/报价/风险展示。
3. 履约评分和接单资格控制。
4. 订单 SLA、争议工单、证据链。

### 第四阶段：资金结算和运营规模化

1. 财务对账、结算批次、打款凭证。
2. 消息通知中心生产化。
3. 风险中心工单化。
4. 报表导出、告警、全局搜索。

## 7. 上线前最低验收清单

| 验收项 | 必须达到 |
|---|---|
| 登录权限 | 后台不能通过前端传 role 获得权限，未登录不能访问平台 API |
| 注册用户 | 商家、接单方、平台成员均可走真实注册/登录/邀请/停用流程 |
| 充值账户 | 商家充值、审核、入账、冻结、扣款、退款、流水查询可完整闭环 |
| 操作审计 | 资金、订单、商家、配置、账号、Agent 人工处理均有审计 |
| 发布失败处理 | 平台可看到失败原因、责任对象、处理状态，并能通知/重试/转人工 |
| 订单履约 | 派单、交付、返修、争议、结算全链路可追溯 |
| 接单方审核 | 入驻、能力、资源、报价有审核状态，未审核不能作为可信派单依据 |
| 资金结算 | 任意订单资金从入账、冻结、释放/扣款到结算可完整追踪 |
| 告警待办 | P0 风险进入后台待办，并可分派责任人或形成处理记录 |
| 生产配置 | Demo 数据、Demo 用户、前端角色切换、mock 成员列表不能出现在生产环境 |
