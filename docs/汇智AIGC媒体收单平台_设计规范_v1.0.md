# 汇智AIGC媒体收单平台设计规范 v1.0

版本：v1.0  
日期：2026-06-25  
适用范围：接单端、发布端报价撮合页、平台端轻运营页  
主参考方向：**巨量星图**  
辅助参考方向：**小红书蒲公英（重点用于入驻流程、身份分流、欢迎引导页）**

---

## 1. 设计结论

本项目后续优化的主设计方向，统一采用：

**巨量星图式的 B 端任务交易平台规范 + 蒲公英式入驻引导规范**

不采用“小红书蒲公英”作为整个平台主框架，原因不是它不好，而是它当前更适合作为：

1. 入驻页
2. 角色分流页
3. 新手欢迎页
4. 轻引导页面

而不适合作为整套交易平台主框架。

最终落地结论：

1. **交易工作台、任务大厅、报价页、订单页：参考巨量星图**
2. **入驻流程、身份选择页、欢迎分流页：参考小红书蒲公英**
3. **整体品牌色可偏红，但工作区交互主色需保持克制**

---

## 2. 为什么选巨量星图

## 2.1 业务结构更接近

汇智AIGC媒体收单平台当前最核心的是：

1. 任务大厅
2. 报价撮合
3. 订单履约
4. 收益结算
5. 服务商经营工作台

巨量星图的页面组织天然更接近这类平台：

1. 左侧导航清晰
2. 顶部经营信息明确
3. 中间是筛选 + 状态 Tab + 表格/列表
4. 页面重心是任务流转，不是品牌展示

而你给的蒲公英截图，本质上是“欢迎入驻 + 身份选择”的门户页，不是任务交易工作台。

## 2.2 用户心智更匹配

你们的接单方、发布方、平台运营方，本质上都在处理：

1. 任务
2. 报价
3. 审核
4. 履约
5. 结算

这类用户更需要：

1. 可扫描的信息结构
2. 强筛选
3. 强状态
4. 高密度列表
5. 稳定、克制、专业的后台感

这也是巨量星图风格的长项。

## 2.3 更适合当前项目阶段

你们现在的问题不是“视觉不够精致”，而是“产品不够像一个成熟平台”。

所以本轮设计目标不应该是：

1. 更品牌化
2. 更营销化
3. 更社交感

而应该是：

1. 更专业
2. 更可信
3. 更易比较
4. 更易决策
5. 更像交易平台

因此，**巨量星图适合作为主规范**。

## 3. 设计定位

本平台的视觉与交互定位如下：

### 3.1 关键词

1. 专业
2. 克制
3. 高效
4. 可扫读
5. 可比较
6. 可决策
7. 可信

### 3.2 不是这些风格

本项目不是：

1. 营销官网
2. 创作者社区
3. 内容种草 App
4. 强情绪化品牌页
5. 大屏可视化驾驶舱

### 3.3 页面气质要求

页面应当让用户第一眼感受到：

1. 这是一个认真做任务交易的平台
2. 我能很快找到待处理事项
3. 我能清楚比较不同方案
4. 这个系统是稳的，不花哨

---

## 4. 风格总原则

## 4.1 主体风格

采用：

1. 浅背景
2. 白色内容卡
3. 弱边框
4. 克制阴影
5. 稳定的蓝灰/品牌红双主色策略
6. 小面积红/橙用于风险或提醒

避免：

1. 大面积红粉色作为主界面基调
2. 过多拟物插画
3. 过度营销感按钮
4. 大卡片堆叠式展示
5. 首页像内容平台而不是工作台

补充说明：

因为当前平台品牌调性偏红色，所以不是完全去红，而是：

1. **品牌识别层可以偏红**
2. **入驻/欢迎流程可以偏蒲公英红系**
3. **任务工作区不能被大面积红色主导**
4. **高频操作区仍应以稳定、低压迫的工作台色系为主**

## 4.2 允许借鉴蒲公英的部分

虽然主工作台不选蒲公英，但以下场景应明确借鉴蒲公英：

1. 入驻身份选择页
2. 新手欢迎页
3. 角色切换页
4. 轻运营说明页
5. 接单方入驻流程页

借鉴点：

1. 居中布局
2. 简洁图标
3. 单屏身份卡选择
4. 强 CTA 按钮

但仅限这些轻页面，**不能反向污染任务大厅和工作台主框架**。

## 5. 布局规范

## 5.1 平台主框架

推荐使用三段式结构：

```text
顶部导航 / 顶栏
左侧主导航
右侧内容工作区
```

### 顶栏

高度建议：

- 64px ~ 72px

包含：

1. 品牌标识
2. 当前模块标题
3. 全局搜索或关键快捷入口
4. 消息通知
5. 用户头像 / 账号菜单

要求：

1. 顶栏固定
2. 背景白色
3. 底部细分割线
4. 不用大面积深色背景

### 左侧导航

宽度建议：

- 220px ~ 240px

导航特点：

1. 一级导航清晰
2. 当前选中态明显
3. 禁止导航项过于花哨
4. 如果二级较多，用折叠组

选中态建议：

1. 浅色背景
2. 主色文字
3. 图标与文字一起高亮

### 内容区

内容区规则：

1. 页面最大宽度不做过强收窄
2. 主要走工作台/后台宽布局
3. 内边距保持 24px
4. 页面模块之间保持 16px ~ 24px 间距

## 5.2 二级工作区布局

从你补充的巨量星图页面看，很多“账户管理 / 财务管理”页并不是只有全局左导航，而是采用：

1. 全局左导航
2. 页面内二级侧栏
3. 右侧内容面板

这类布局非常适合你们后续的：

1. 接单方账户中心
2. 财务中心
3. 认证中心
4. 账号绑定中心

推荐结构：

```text
全局导航 220~240px
页面内二级导航 220~260px
右侧内容区自适应
```

二级导航规范：

1. 白底卡片容器
2. 分组标题可折叠
3. 当前子页高亮为浅红底或浅品牌底
4. 每个导航项高度稳定
5. 子项文字不要过密

适用场景：

1. 账户管理
2. 财务管理
3. 认证资料
4. 媒体绑定

不适用场景：

1. 任务大厅
2. 我的订单
3. 比价页

## 5.3 右侧帮助浮层规范

从巨量星图图中可以看出，右侧常驻帮助浮层是稳定存在的。

你们后续可以保留类似结构，但必须克制：

1. 帮助
2. 联系
3. 客服
4. 反馈

规范：

1. 固定在右侧底部
2. 纵向排列
3. 图标统一尺寸
4. 白底浅边框
5. Hover 才增强

禁止：

1. 浮层比主内容更抢眼
2. 使用大面积品牌红
3. 在所有页面都弹出强提示气泡

## 6. 页面结构规范

## 6.1 工作台页

适用于：

1. 接单端首页
2. 平台运营首页
3. 发布端任务总览页

结构顺序：

1. 页面标题 + 辅助说明
2. 核心经营指标卡
3. 待办事项
4. 推荐任务 / 推荐动作
5. 最近动态 / 最近订单

禁止：

1. 一打开就全是大表格
2. 一打开就堆很多大色块 KPI
3. 一打开就用营销风 Banner

补充要求：

结合你补充的巨量星图概览图，工作台页应采用“上轻下重”的结构：

1. 顶部是两个并列的待完成动作卡
2. 中部是账户身份与收益摘要
3. 下部才是公告、任务概览、空状态

工作台页中允许存在一张运营 Banner，但必须满足：

1. 仅 1 张
2. 作为辅助说明，不是主视觉
3. 宽度不超过主内容区的一半
4. 不得压过任务卡和收益卡

## 6.2 列表页

适用于：

1. 任务大厅
2. 我的报价
3. 我的订单
4. 发单管理

结构顺序：

1. 页面标题
2. 筛选器区
3. 状态 Tab 区
4. 列表 / 表格区
5. 分页或加载更多

筛选器要求：

1. 一行优先展示核心筛选
2. 次要筛选可换行
3. 有“重置”
4. 有明确筛选项标签

补充要求：

从巨量星图财务页可以总结出一个更成熟的列表页模板：

1. 顶部先展示该模块摘要
2. 中间是筛选器
3. 下方是表格
4. 表格为空时仍保留完整表头
5. 底部保留分页器

因此你们的列表页不要只做：

1. 标题
2. 一张空表

而要补足：

1. 摘要区
2. 筛选区
3. 表头区
4. 空态区
5. 分页区

## 6.3 详情页

适用于：

1. 任务详情
2. 报价详情
3. 订单详情

结构顺序：

1. 返回入口
2. 标题 + 状态 + 关键动作
3. 核心摘要卡
4. 详细信息模块
5. 时间轴 / 操作记录 / 交付记录

要求：

1. 详情页不是长表单
2. 先看摘要，再看细节
3. 关键动作固定在首屏

## 6.4 账户管理页模板

适用于：

1. 基础信息
2. 实名认证
3. 媒体账号绑定
4. 协议与开通状态

结合巨量星图账户管理图，统一结构建议：

1. 页面内二级导航
2. 基础信息卡
3. 认证状态卡
4. 账号绑定卡
5. 协议说明卡

### 基础信息卡

字段展示方式建议采用“信息网格”而不是长表单：

1. 左上是字段名
2. 下方是当前值
3. 右侧是编辑图标或次按钮

适合展示：

1. 联系方式
2. 平台 ID
3. 合作品牌
4. 自我介绍
5. 账户状态

要求：

1. 缺失值用统一文案，如“暂未填写”
2. 编辑入口轻量，不用大按钮
3. 字段列数稳定，优先 3~4 列网格

### 认证状态卡

认证卡必须是“状态 + 动作”的结构，不是纯说明文案。

例如：

1. 未实名
2. 已实名待审核
3. 已通过
4. 已驳回

右侧必须有明确动作：

1. 去认证
2. 查看进度
3. 重新提交

### 媒体绑定卡

参考巨量星图的账号绑定区，建议用“平台行”而不是大表格。

每一行包含：

1. 平台 Logo
2. 平台名称
3. 当前绑定状态
4. 已绑定账号摘要
5. 操作按钮

绑定状态文案必须统一：

1. 未绑定
2. 已绑定
3. 绑定中
4. 绑定失效

## 6.5 财务管理页模板

适用于：

1. 结算记录
2. 提现记录
3. 收益总览
4. 可提现金额页

结合你补充的巨量星图财务截图，财务页统一模板如下：

1. 二级导航切换财务模块
2. 顶部摘要说明
3. KPI 小卡片
4. 筛选器区
5. 表格区
6. 空状态与分页

### 财务摘要区

要求：

1. 标题必须清晰
2. 可附带时间口径说明
3. 说明文字置于标题右侧或标题下方

### KPI 小卡片

财务页中的指标卡不应太大，建议用并列 3 卡或 4 卡。

推荐字段：

1. 累计收入
2. 已提现金额
3. 待提现金额
4. 本月收入

规则：

1. 卡片尺寸一致
2. 标题在上，金额在下
3. 金额字体突出，但不夸张
4. 不要使用厚重图表背景

### 提现页

提现页顶部应先告诉用户“当前是否具备提现资格”，而不是直接给表格。

建议结构：

1. 提现资格状态卡
2. 实名/收款绑定补全动作
3. 提现记录表

如果未实名：

1. 首屏就给出阻断说明
2. 提供主按钮“去实名认证”
3. 提现记录表仍可展示，但操作不可用

## 7. 视觉规范

## 7.1 色彩体系

主色采用“工作台蓝灰 + 品牌红点缀”的组合，而不是纯蓝，也不是全站红色主导。

推荐 Token：

```css
:root {
  --hz-bg-page: #f6f8fb;
  --hz-bg-card: #ffffff;
  --hz-bg-subtle: #f9fafc;

  --hz-border: #e6ebf2;
  --hz-border-subtle: #eef2f6;

  --hz-text-title: #1f2329;
  --hz-text-primary: #344054;
  --hz-text-secondary: #667085;
  --hz-text-muted: #98a2b3;

  --hz-primary: #e11d48;
  --hz-primary-hover: #be123c;
  --hz-primary-bg: #fff1f4;

  --hz-workbench-accent: #2563eb;
  --hz-workbench-accent-hover: #1d4ed8;
  --hz-workbench-accent-bg: #eff6ff;

  --hz-success: #16a34a;
  --hz-success-bg: #ecfdf3;

  --hz-warning: #f59e0b;
  --hz-warning-bg: #fffbeb;

  --hz-danger: #ef4444;
  --hz-danger-bg: #fef2f2;

  --hz-info: #3b82f6;
  --hz-info-bg: #eff6ff;
}
```

### 色彩使用规则

1. 品牌红：品牌识别、入驻页主按钮、局部强调
2. 工作台蓝：筛选选中、表格交互、信息型主操作
3. 绿色：完成、通过、可结算
4. 橙色：待处理、提醒、进行中
5. 红色：风险、超时、拒绝、异常

执行规则：

1. **入驻链路优先使用品牌红**
2. **任务交易工作区优先使用工作台蓝**
3. **风险语义红与品牌红要区分深浅**

## 7.2 字体规范

建议层级：

1. 页面标题：24px / 700
2. 模块标题：16px / 700
3. 卡片标题：14px / 600
4. 正文：14px / 400~500
5. 辅助说明：12px
6. 状态标签：11px~12px
7. KPI 数字：28px~32px / 700

要求：

1. 不要用过大的 hero 字体
2. 不要用负字间距
3. 不要过度依赖灰字作为正文

## 7.3 圆角规范

统一要求：

1. 卡片圆角：8px
2. 输入框圆角：6px
3. 按钮圆角：6px
4. 弹窗圆角：8px

禁止：

1. 大面积 16px~24px 圆角
2. 过多胶囊形大按钮

## 7.4 阴影规范

阴影必须克制。

推荐：

```css
box-shadow: 0 6px 20px rgba(15, 23, 42, 0.04);
```

禁止：

1. 浓重投影
2. 多层悬浮阴影
3. 卡片靠阴影而不是边框建立层级

## 7.5 间距与留白规范

你补充的巨量星图图里，一个很明显的特征是：留白很大，但结构不散。

因此本项目要遵守：

1. 页面外层留白大于组件内层留白
2. 卡片之间间距统一
3. 表格上方筛选器与表格之间保留完整呼吸感

推荐间距：

1. 页面区块间距：24px
2. 卡片之间：16px
3. 卡片内区块：16px 或 20px
4. 标题与说明：8px
5. 筛选器项之间：12px

禁止：

1. 模块彼此贴太近
2. 表格和筛选器紧挨着没有呼吸感
3. 空态插图与文案贴在一起

## 8. 组件规范

## 8.1 卡片

卡片是主组件。

统一规则：

1. 白底
2. 1px 浅边框
3. 8px 圆角
4. 轻阴影可选
5. 内边距 16px 或 20px

禁止：

1. 卡片里再套大卡片
2. 卡片左侧粗色条
3. 卡片背景大面积渐变

## 8.2 按钮

按钮分三类：

1. 主按钮
2. 次按钮
3. 文字按钮

### 主按钮

用于：

1. 提交报价
2. 确认报价
3. 立即领取
4. 进入下一步

样式：

1. 工作台页默认蓝底白字
2. 入驻页可用品牌红底白字
2. 中等高度
3. 带 hover

### 次按钮

用于：

1. 返回
2. 查看详情
3. 取消
4. 重置筛选

样式：

1. 白底浅边框
2. 深色文字

### 危险按钮

仅用于：

1. 拒绝
2. 删除
3. 撤回

必须有二次确认。

## 8.3 状态标签

状态标签必须统一，不能每个页面自己发明风格。

推荐映射：

1. 待报价：蓝灰底
2. 报价中：橙底
3. 待确认：橙底
4. 已中标：蓝底或绿底
5. 履约中：蓝底
6. 待验收：橙底
7. 已完成：绿底
8. 已取消：灰底
9. 争议中：红底

要求：

1. 标签短小
2. 颜色统一
3. 文案稳定

## 8.4 表格

适用于：

1. 报价对比
2. 订单列表
3. 运营审核列表

规范：

1. 表头浅灰底
2. 行高稳定
3. 重点列允许加粗
4. 操作列固定在右侧
5. 状态列宽度稳定

禁止：

1. 表格里堆很多按钮
2. 每行样式差异过大
3. 表格列宽跟随文案乱跳

补充要求：

1. 空状态下保留表头
2. 表格底部保留分页器占位
3. 横向滚动允许存在，但必须可理解
4. 金额列、状态列、操作列宽度应固定

## 8.4.1 财务表格特殊规范

财务表格建议固定包含：

1. 时间
2. 单号 / ID
3. 名称 / 类型
4. 金额
5. 来源
6. 状态
7. 操作

要求：

1. 金额列右对齐或视觉上更稳
2. 状态列不要过宽
3. 操作列始终在最右

## 8.4.2 空表格模板

巨量星图空表格处理得比较成熟，建议照这个原则：

1. 表头保留
2. 空插图居中
3. 文案极简
4. 允许有“去看看任务”“去绑定账号”类引导动作

不要做成：

1. 整个表格消失
2. 只剩一句“暂无数据”
3. 空态把页面结构打断

## 8.5 筛选器

筛选器应模仿巨量星图这种“强筛选、高可用”风格。

要求：

1. Select、日期、搜索框统一高度
2. 一行内布局整齐
3. 有重置
4. 默认值明确
5. 禁止奇怪的占位文案

补充要求：

结合巨量星图财务页，筛选器应分为三层：

1. 时间范围
2. 业务类型
3. 搜索条件

建议优先级：

1. 时间
2. 状态
3. 类型
4. 关键词

筛选器容器本身应是一张轻卡片或融入内容卡顶部，不建议裸露在页面背景上。

## 8.6 空状态

空状态要克制，不能幼态化。

要求：

1. 小插图可有，但不抢戏
2. 主文案短
3. 有明确下一步动作

例如：

1. 暂无待报价任务
2. 先完善接单平台偏好
3. 去任务大厅看看

结合巨量星图截图，空状态统一模板建议为：

1. 轻插图
2. 主文案
3. 次文案可省略
4. 1 个主动作按钮或文字链接

空状态适用动作示例：

1. 查看更多商机
2. 去绑定账号
3. 去实名认证
4. 返回任务大厅

## 8.7 公告通知卡

巨量星图概览页里“公告通知”模块值得借鉴。

适用于：

1. 接单端首页
2. 发布端工作台
3. 平台端首页

规范：

1. 标题在左
2. 轮播或分页控制在右
3. 列表项高度统一
4. 重要公告有标签
5. 详情入口放右侧

不要：

1. 把公告做成大图文 Feed
2. 抢占主业务区

## 8.8 轻 Banner 规范

巨量星图概览页中的“入驻须知”属于轻 Banner，而不是营销 Hero。

你们如果使用类似模块，必须遵守：

1. 只占一个卡片位
2. 不跨整屏
3. 与公告/任务卡并列
4. 用于规则说明、活动提示、新手引导

禁止：

1. 每页都有大 Banner
2. Banner 盖过任务列表
3. Banner 使用强营销文案

## 9. 三端具体风格要求

## 9.1 接单端

定位：

服务商经营工作台

风格重点：

1. 明确经营状态
2. 强任务感
3. 强决策感
4. 可看收益
5. 可看履约

接单端禁止做成：

1. 创作者个人主页风
2. 社区内容流风
3. 红粉品牌页风

但以下页面例外：

1. 入驻欢迎页
2. 身份分流页
3. 首次开通引导页

这些页面允许更接近蒲公英。

接单端还应进一步区分两种视觉状态：

1. 未完成入驻时：更像“开通工作台”
2. 已完成入驻后：更像“任务经营后台”

未完成入驻时可参考你补充的巨量星图概览页：

1. 顶部展示待完成动作卡
2. 中部展示身份与绑定状态
3. 下方展示任务空状态

这样比单独放一个 onboarding 表单更有平台感。

## 9.2 发布端

定位：

品牌方的任务发起与决策工作台

风格重点：

1. 看得懂任务
2. 看得懂报价
3. 看得懂下一步动作
4. 不暴露不必要的财务拆账细节

发布端重点像：

1. 采购/媒介决策后台
2. 任务协作台

发布端也应借鉴巨量星图的两点：

1. 强筛选结构
2. 状态 Tab + 表格主工作区

尤其在比价页、发单管理页中，不能做成内容卡拼贴页。

## 9.3 平台端

定位：

轻运营与供给管理后台

风格重点：

1. 更克制
2. 更高密度
3. 更少装饰
4. 更强调状态管理与审计感

平台端如果涉及财务、审核、账号管理，也应优先采用你补充截图中的二级侧栏结构，而不是所有模块都混在一级导航里。

## 10.1 必须向巨量星图靠拢的页面

以下页面统一以巨量星图为主参考：

1. 接单端首页
2. 任务大厅
3. 我的报价
4. 我的订单
5. 发布端发单管理
6. 发布端比价页
7. 平台端审核页
8. 接单端账户中心
9. 接单端财务页
10. 接单端提现记录页

这些页面的核心结构都应偏：

1. 左侧导航
2. 顶部标题
3. 中部筛选
4. 下方状态 Tab
5. 列表/表格主工作区

如果是账户/财务类页面，则进一步偏：

1. 全局左导航
2. 页面内二级导航

## 10.2 可以借鉴蒲公英的页面

以下页面明确参考蒲公英：

1. 接单方入驻欢迎页

3. 博主 / 买手 / MCN 类似的角色分流页
4. 新手引导页
5. 入驻步骤页

这些页面允许：

1. 居中布局
2. 三列卡片
3. 更轻一点的品牌化视觉
4. 更明显的红色品牌按钮

但必须保持整体简洁。

## 11. 开发实现要求

## 11.1 前端实现必须遵守

1. 页面先按本规范定结构，再接数据
2. 不允许因为本地 Mock 不全而降级布局
3. 不允许随手加营销风模块
4. 不允许把接单端做成社交平台页面

## 11.2 UI 一致性要求

同一类元素必须统一：

1. 状态标签
2. 按钮风格
3. 表单尺寸
4. 筛选器尺寸
5. 卡片结构
6. 标题层级

## 11.3 验收要求

后续开发 Agent 交付页面时，必须自查：

1. 这个页面是否更像巨量星图，而不是像活动页？
2. 这个页面是否能快速处理任务，而不是只展示内容？
3. 这个页面是否适合高频工作，而不是只适合演示？
4. 这个页面的主色是否克制，没有被红粉色主导？

---

## 12. 最终结论

本项目的主设计规范结论如下：

1. **主方向：巨量星图，用于任务交易工作台**
2. **辅方向：蒲公英，用于入驻流程与身份分流**
3. **整体气质：专业、克制、高效、任务驱动**
4. **主框架：B 端工作台，不做内容社区风**
5. **主色策略：品牌红用于入驻与品牌识别，工作台蓝用于高频交易操作**

后续所有页面优化，如果没有特别说明，都默认按这份规范收敛。
