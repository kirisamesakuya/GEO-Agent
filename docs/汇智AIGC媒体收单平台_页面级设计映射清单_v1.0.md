## 1. 文档目的

本文用于把“整体设计方向”进一步拆到页面级别，方便其他 Agent 直接执行。

本文回答四个问题：

1. 每个页面应参考哪种模板
2. 每个页面应采用什么布局
3. 每个页面必须包含哪些模块
4. 每个页面禁止出现哪些偏差

---

## 2. 页面映射总原则

页面参考分三类：

1. **巨量星图工作台型**
   - 适用于任务、报价、订单、财务、账户、后台管理
2. **蒲公英入驻型**
   - 适用于入驻欢迎、身份分流、角色选择、新手引导
3. **混合型**
   - 页面上半区偏引导，下半区偏工作台

默认规则：

1. 只要页面核心任务是“处理任务、报价、订单、资金、审核”，就走巨量星图型
2. 只要页面核心任务是“选择身份、开通权限、开始入驻”，就走蒲公英型
3. 不能因为品牌色偏红，就把所有工作台页面都做成蒲公英风

## 3. 接单端页面映射

## 3.1 接单端首页 `ProviderHomeView`

### 参考方向

**巨量星图概览页**

### 页面定位

服务商经营工作台首页

### 页面结构

1. 顶部待完成动作卡
2. 中部身份 / 收益摘要卡
3. 公告与规则提示区
4. 推荐任务区
5. 待办订单 / 空状态区

### 必须包含

1. 今日待处理事项
2. 可提现金额
3. 报价待确认数
4. 履约中订单数
5. 推荐任务
6. 公告通知

### 禁止

1. 首页只放 3 张数字卡
2. 首页像营销页 Banner 墙
3. 首页完全没有“下一步该做什么”

---

## 3.2 任务大厅 `ProviderTaskView`

### 参考方向

**巨量星图任务大厅**

### 页面定位

接单方发现任务并决策是否报价的主页面

### 页面结构

1. 页面标题
2. 筛选器区
3. 状态 Tab
4. 任务列表
5. 详情抽屉或详情页

### 必须包含

1. 平台筛选
2. 行业筛选
3. 内容方向筛选
4. 时间筛选
5. 搜索
6. 匹配度与匹配原因
7. 建议报价区间
8. 任务状态

### 禁止

1. 只展示任务名和品牌名
2. 只有匹配百分比，没有解释
3. 任务详情像原始 JSON 信息堆砌

## 3.3 报价提交页 `ProviderSubmitQuoteView`

### 参考方向

**巨量星图任务承接页 + 标准化方案卡**

### 页面定位

接单方提交结构化报价方案

### 页面结构

1. 任务摘要
2. 建议区间提示
3. 报价输入区
4. 履约承诺区
5. 交付证明区
6. 自动金额计算区
7. 提交按钮区

### 必须包含

1. P0 到手价
2. 成交价 G 自动展示
3. 平台服务费 F 自动展示
4. 超区间提示
5. 超区间原因输入
6. 媒体 / 账号说明
7. 预计上线时间
8. 是否含链接 / 截图 / 收录证明

### 禁止

1. 只保留几个表单输入框
2. 不展示金额关系
3. 超区间时没有阻断提示

## 7. 可直接给其他 Agent 的执行格式

建议其他 Agent 在做每个页面前，先写一个 5 行小卡片：

1. 页面名称
2. 参考模板
3. 页面定位
4. 必须模块
5. 禁止偏差

示例：

```md
页面：接单端首页
参考模板：巨量星图概览页
定位：服务商经营工作台
必须模块：待办卡、收益卡、公告、推荐任务、任务空态
禁止偏差：营销大 Banner、低密度大卡片、无下一步动作
```

---

## 8. 最终结论

后续页面开发时，统一按下面这条执行：

1. 入驻相关页面看蒲公英
2. 任务交易页面看巨量星图
3. 账户与财务页优先参考你补充的巨量星图账户/财务截图
4. 页面不能只“看起来像”，必须连结构、信息密度、空状态、筛选器、分页器一起收敛

本文应与前两份文档一起使用，不单独使用。
