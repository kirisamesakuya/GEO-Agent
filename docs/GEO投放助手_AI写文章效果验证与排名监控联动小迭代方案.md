# GEO 投放助手：AI 写文章效果验证与排名监控联动小迭代方案

版本：v1.3.2 文章效果验证专项  
日期：2026-06-05  
关联文档：`GEO投放助手_AI写文章调用链路小版本迭代方案.md`、`GEO投放助手_Hermes连调前Web端功能补齐迭代计划.md`、`GEO投放助手_发布端信息架构优化方案.md`  
开发口径：本小版本只补齐“AI 写文章是否有效”的验证闭环；优先复用现有排名监控、内容库、发布记录和 GEO 报告能力，不新增完整投放归因系统，不承诺 AI 一定引用或推荐。

---

## 1. 检查结论

当前 AI 写文章专项已经补齐了“从 GEO 报告/品牌资料/知识库生成文章”的调用链路，但还缺少生成后效果验证。

建议把排名监控定位为 AI 写文章的效果验收器：

```text
排名监控 / GEO 分析发现缺口
        ↓
按缺口生成 AI 文章
        ↓
内容库人工确认
        ↓
发布并留证
        ↓
排名监控 7 / 14 / 30 天复测
        ↓
回写文章效果分、报告效果模块和下一轮选题建议
```

这样 AI 写文章不再只是内容生产，而是 GEO 闭环中的“补缺口动作”。

---

## 2. 当前缺口

| 缺口 | 当前问题 | 补齐方向 | 优先级 |
|---|---|---|---|
| 写作目标未绑定排名问题 | 文章可根据报告生成，但没有明确绑定要改善哪些 AI 问题 | 生成任务记录 `targetQuestions`、`targetPlatforms`、`sourceIndexPlanId` | P0 |
| 发布前后无对照 | 内容库文章没有发布前基线快照 | 生成文章时保存来源排名快照或来源 GEO 报告指标 | P0 |
| 发布后不自动复测 | 排名监控计划与文章发布记录没有联动 | 发布成功后创建 7/14/30 天复测计划 | P0 |
| 文章效果无回写 | 内容详情只看文章本身，不看是否改善提及率/收录 | 内容库增加“效果验证”面板 | P1 |
| 报告缺少文章贡献解释 | GEO 报告展示提及率和缺口，但不说明哪些文章带来变化 | 报告增加“文章效果验证”模块 | P1 |
| 选题无法反哺 | 复测失败后没有给下一轮写作建议 | 根据复测结果生成下一轮内容建议 | P2 |

## 3. 产品边界

### 3.1 这个小版本要做什么

1. 从排名监控结果中选择低提及问题、竞品强问题、未覆盖关键词，一键进入 AI 写文章。
2. AI 文章生成任务记录来源问题、来源采样批次和目标平台。
3. 内容发布成功后，自动创建复测计划或复测任务。
4. 复测结果回写到内容库文章详情。
5. GEO 报告中展示“文章发布前后变化”。

### 3.2 这个小版本不做什么

1. 不承诺 AI 平台一定引用或推荐。
2. 不做完整线索转化归因。
3. 不把文章效果直接作为接单结算依据。
4. 不要求真实 Hermes 全自动发布成功后才能启用；mock / direct executor 阶段也可先落字段和 UI。
5. 不替代人工内容审核。

## 4. 核心流程

### 4.1 从排名监控生成文章

用户在排名监控中看到某个问题表现不好：

| 问题 | 平台 | 当前表现 | 建议动作 |
|---|---|---|---|
| 南京种植牙哪家靠谱 | 豆包 | 未提及品牌，竞品 A 出现 | 生成问答型文章 |
| 隐形矫正怎么选 | DeepSeek | 品牌出现但位置靠后 | 生成科普型文章 |
| 云杉口腔怎么样 | Kimi | 品牌出现，缺少案例信息 | 生成案例型文章 |

点击“生成补缺文章”后进入生成 GEO 文章页，并预填：

| 字段 | 来源 |
|---|---|
| `source` | `indexing_result` |
| `sourceIndexPlanId` | 当前排名监控计划 |
| `sourceIndexResultIds` | 被选中的采样结果 |
| `targetQuestions` | 被选中的 AI 问题 |
| `targetPlatforms` | 被选中的 AI 平台 |
| `keywords` | 问题关联关键词 |
| `contentDirection` | 根据缺口推荐 FAQ / 问答 / 测评 / 案例 |

---

### 4.2 生成文章时保存验证基线

文章生成任务需要保存发布前基线：

```json
{
  "effectBaseline": {
    "source": "indexing_result",
    "capturedAt": "2026-06-05T12:00:00.000Z",
    "targetQuestions": ["南京种植牙哪家靠谱"],
    "targetPlatforms": ["豆包", "DeepSeek"],
    "brandMentionRate": 0,
    "competitorMentions": ["竞品 A"],
    "answerSnapshots": [
      {
        "platform": "豆包",
        "question": "南京种植牙哪家靠谱",
        "brandMentioned": false,
        "rank": null,
        "summary": "回答中主要提到竞品 A 和竞品 B"
      }
    ]
  }
}
```

短期可放入 `ContentItem.generationMetaJson` 或 `qualityChecksJson`；正式版建议拆成独立效果验证字段。

---

### 4.3 发布后创建复测计划

当文章进入发布记录并且有链接时，创建复测计划：

| 复测点 | 目的 | 是否 P0 |
|---|---|---|
| T+7 天 | 判断是否初步收录/提及 | 是 |
| T+14 天 | 判断 AI 回答是否开始变化 | 是 |
| T+30 天 | 判断是否进入月度复盘 | 是 |

复测任务可以复用现有排名监控能力：

```json
{
  "planName": "文章效果复测：南京种植牙哪家靠谱",
  "brandName": "云杉口腔",
  "sourceContentItemId": "content-item-id",
  "sourcePublishRecordId": "publish-record-id",
  "questions": ["南京种植牙哪家靠谱"],
  "platforms": ["豆包", "DeepSeek"],
  "schedule": ["T+7", "T+14", "T+30"]
}
```

---

### 4.4 复测后回写文章效果

复测完成后，内容库文章详情展示：

| 指标 | 说明 |
|---|---|
| 搜索收录状态 | 发布链接是否可被搜索或平台检索 |
| 品牌提及变化 | 发布前后品牌是否出现、提及率变化 |
| 竞品提及变化 | 竞品是否仍压制品牌 |
| AI 回答摘要变化 | 回答是否开始引用文章中的事实或表达 |
| 引用来源 | 是否出现发布链接、站点、平台账号等来源 |
| 效果判断 | 有效 / 待观察 / 无明显变化 |

效果判断建议：

| 判断 | 条件 |
|---|---|
| 有效 | 品牌从未提及变为提及，或排名/位置明显前移，或回答引用了文章事实 |
| 待观察 | 链接已发布但未收录，或只完成 T+7 复测 |
| 无明显变化 | T+30 后品牌提及、竞品压制、引用来源均无改善 |

## 5. 页面调整

### 5.1 排名监控页

在采样结果列表增加“生成补缺文章”动作。

```text
┌────────────────────────────────────────────────────────────┐
│ 排名监控                                                   │
├────────────────────────────────────────────────────────────┤
│ 问题：南京种植牙哪家靠谱                                   │
│ 平台：豆包                                                  │
│ 状态：品牌未提及 · 竞品 A 出现                              │
│ [查看回答] [生成补缺文章] [加入复测组]                       │
└────────────────────────────────────────────────────────────┘
```

功能点：

1. 可单选或多选采样结果。
2. 多选后批量生成文章任务。
3. 自动带入品牌、平台、问题、关键词和当前回答摘要。
4. 如果已有文章绑定同一问题，提示“已有补缺文章，可查看效果”。

---

### 5.2 生成 GEO 文章页

在现有“生成来源”中新增：

| 来源 | 说明 |
|---|---|
| 按品牌资料生成 | 原能力 |
| 根据 GEO 报告生成 | v1.3.1 能力 |
| 根据排名缺口生成 | 本小版本新增 |

右侧摘要增加：

```text
排名缺口

- 竞品出现：竞品 A、竞品 B
```

## 7. 迭代拆分

### P0：最小验证闭环

| 编号 | 功能 | 说明 |
|---|---|---|
| P0-01 | 排名监控结果生成文章 | 从低提及问题进入 AI 写文章 |
| P0-02 | 文章保存目标问题和基线 | 记录 `targetQuestions`、`targetPlatforms`、baseline |
| P0-03 | 发布后创建复测计划 | 自动生成 7/14/30 天复测任务 |
| P0-04 | 内容库展示验证状态 | 待复测 / 待观察 / 有效 / 无明显变化 |

### P1：报告与工作台可见

| 编号 | 功能 | 说明 |
|---|---|---|
| P1-01 | 内容详情效果面板 | 展示发布前后采样对比 |
| P1-02 | GEO 报告文章效果模块 | 报告解释哪些文章对应哪些变化 |
| P1-03 | 工作台增加文章效果待办 | T+7/T+14/T+30 复测失败或待处理进入待办条 |

### P2：反哺下一轮写作

| 编号 | 功能 | 说明 |
|---|---|---|
| P2-01 | 复测失败生成改写建议 | 根据无效问题生成下一轮选题 |
| P2-02 | 文章效果评分 | 汇总内容质量、收录、提及变化形成效果分 |
| P2-03 | Prompt 反哺 | 将有效文章结构沉淀为写作模板 |

## 8. 验收标准

1. 用户可从排名监控中选择至少 1 条低提及采样结果，并生成 AI 文章任务。
2. 生成后的文章详情能看到目标问题、目标平台、来源采样和发布前基线。
3. 文章发布成功后，系统能创建或提示创建 7 / 14 / 30 天复测计划。
4. 复测完成后，内容库能展示发布前后品牌提及变化和效果判断。
5. GEO 报告能展示至少一条“文章 → 目标问题 → 复测变化”的对应关系。
6. 页面文案不得承诺“保证被 AI 推荐”“保证排名提升”。

---

## 9. 建议实现顺序

1. 先补数据关系：`ContentItem` 记录来源排名结果、目标问题、目标平台和 baseline。
2. 再补排名监控入口：“生成补缺文章”。
3. 再补发布后复测计划。
4. 最后补内容库和报告展示。

这样不会阻塞 v1.3.1 的真实写作链路，也能尽快让 AI 写文章具备可验证价值。
